# 25 — Operations & Troubleshooting Runbook

## 1. Tujuan

Production support harus dapat menjawab "kenapa charging tidak berubah?" tanpa menebak atau membaca puluhan sysfs node manual.

## 2. Required status

```text
daemon lifecycle
policy state/reason
config/schema version
profile/capabilities
ownership phase
hardware desired/applied/actual/verified
last operation ID
last error/category
retry_at/failure count
snapshot age
netlink state
```

## 3. Diagnosis tree

```text
Daemon alive?
 ├─ no → lifecycle/crash recovery
 └─ yes
     Config valid?
      ├─ no → config runbook
      └─ yes
          Capability valid?
           ├─ no → profile runbook
           └─ yes
               Fresh snapshot?
                ├─ no → reader/runbook
                └─ yes
                    Desired == Actual?
                     ├─ no → controller/reconcile
                     └─ yes
                         Verified?
                          ├─ no → verification
                          └─ yes → investigate external actor
```

## 4. Stuck charging

Collect:

```text
policy state
capacity/temp/current/status/online
hardware desired vs actual
last operation
verification result
retry state
```

Jangan langsung menjalankan `set_charging()` manual dari shell karena dapat menghilangkan evidence ownership.

## 5. Verification failed

Check:

```text
control node readback
node availability
vendor delay
current/status semantics
external actor
```

Jika repeated failure, bounded backoff harus terlihat.

## 6. Config invalid

Preserve original file. Diagnostic harus menyebut parse/validation/schema category dan lokasi field bila aman.

## 7. Logging

Gunakan transition-based logs:

```text
policy changed
hardware operation started
hardware operation completed
verification failed
recovery entered
```

Polling normal tidak perlu spam setiap cycle. Repeated errors di-rate-limit.

## 8. Support bundle

Bundle offline sebaiknya berisi:

```text
version/build
Android/kernel info
profile/capabilities
config schema summary (redacted)
policy/hardware state
ownership phase
recent operation/error summary
netlink health
```

Jangan memasukkan secret atau raw unbounded payload.

## 9. Recovery commands

Read-only commands aman secara default. Mutation/recovery command harus restricted dan menjelaskan side effect sebelum execution.

## 10. Testing runbooks

Setiap failure scenario harus punya fixture/log example:

```text
[ ] stuck charging
[ ] stuck not charging
[ ] verification fail
[ ] node absent
[ ] config corrupt
[ ] stale ownership
[ ] netlink dead
[ ] external interference
```

## 11. Acceptance criteria

1. Operator dapat melihat desired/actual/verified.
2. Error memiliki category dan operation ID.
3. Runbook tidak membutuhkan internet.
4. Diagnostic output dapat dibagikan dengan aman.
5. Recovery tidak bypass controller.
