# 25 — Operations & Troubleshooting Runbook

## Tujuan
Production daemon harus dapat didiagnosis tanpa source-level debugging di device.

## Status yang wajib tersedia
```text
daemon state
policy state + reason
config version
profile/capabilities
ownership state
actual hardware state
verification state
last operation ID
last error + category
retry/backoff
snapshot age
netlink health
```

## Diagnosis flow
```text
Daemon running?
 -> Config valid?
 -> Capability valid?
 -> Ownership recovered?
 -> Fresh snapshot?
 -> Desired state?
 -> Actual state?
 -> Verification?
 -> External actor?
 -> Retry/backoff?
```

## Commands
CLI sebaiknya menyediakan read-only diagnostics yang aman: status ringkas, status verbose, capabilities, config validation, dan health. Recovery command dipisahkan dan diberi guard.

## Logging
Structured logs dengan level yang tepat. Hindari spam pada polling normal; gunakan transition-based logs untuk state changes dan rate limit untuk repeated errors.

## Support bundle
Sediakan output diagnostik yang tidak membocorkan secret dan tidak membutuhkan akses internet. Bundle harus menyertakan version, profile, capability, state machine, dan recent error summary.

## Acceptance criteria
1. Masalah `not charging`, `stuck`, `verification failed`, dan `config invalid` memiliki runbook berbeda.
2. Operator dapat mengetahui desired vs actual tanpa membaca sysfs manual.
3. Log error berulang di-rate-limit.
4. Diagnostic output aman untuk dibagikan.
