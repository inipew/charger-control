# 09 — SCHEDULER, EMA, NETLINK & POWER EFFICIENCY

## Prinsip

Scheduler adalah wake-up optimizer, bukan safety authority.

```text
Policy → WHAT
Scheduler → WHEN
```

## Scheduler input

Gunakan actual semantic state:

```text
online
charging
capacity
temperature
controller deadline
retry deadline
```

Jangan infer `is_charging` dari `StopReason::None` atau policy state.

## Deadline composition

Controller menyediakan:

```rust
fn next_deadline(&self) -> Option<Instant>
```

yang mencakup:

```text
verification
retry
reconciliation
```

Monitor memilih earliest deadline bersama timer policy/netlink.

## Adaptive polling

EMA boleh digunakan untuk optimisasi ETA, tetapi tidak boleh menjadi safety mechanism.

Reset/reject prediction pada:

- invalid dt;
- impossible capacity jump;
- unplug/replug;
- long suspend/sleep gap;
- policy config change;
- sensor invalid.

## Capacity rate

Battery percentage adalah quantized fuel-gauge signal. Jangan memperlakukan setiap perubahan 1% sebagai continuous physical rate.

Gunakan minimum observation interval dan plausibility filter sebelum update EMA.

## Thermal scheduling

Jika dekat thermal cutoff, scheduler harus memilih interval konservatif dan mengabaikan ETA optimistik.

Safety boundary selalu mengalahkan power-saving.

## Unplugged

Saat offline, tidak perlu melakukan aggressive charging ETA prediction. Gunakan heartbeat panjang yang tetap memungkinkan perubahan charger terdeteksi jika Netlink tidak tersedia.

## Netlink

Event:

```text
ACTION=change
SUBSYSTEM=power_supply
```

harus menyebabkan invalidate/re-read, bukan langsung menetapkan state final.

## Netlink reconnect

Gunakan satu retry scheduler:

```text
failure
→ schedule_retry(now)
→ exponential backoff
→ success resets backoff
```

Hindari dua fungsi berbeda yang sama-sama mengubah `reconnect_at` dan backoff.

## poll()

```text
>0 → process events
0  → timeout/deadline
<0 → error
EINTR → retry
```

Periksa `POLLERR`, `POLLHUP`, `POLLNVAL`.

## Resource

Gunakan RAII FD (`OwnedFd` atau wrapper). Netlink socket tidak boleh bergantung pada process exit untuk cleanup.

## Port ID

Untuk Netlink, pertimbangkan membiarkan kernel memilih port ID (`nl_pid=0`) daripada mengasumsikan PID process sebagai identifier yang tepat.

## Acceptance

Power efficiency dianggap benar jika daemon:

- tidur sampai deadline terdekat;
- tidak polling 2 detik hanya untuk menunggu retry 30 detik;
- tetap aman tanpa Netlink;
- prediction failure kembali ke conservative schedule;
- tidak menggunakan policy state sebagai proxy actual charging state.
