# 09 — Scheduler, EMA & Netlink

## 1. Responsibility

Scheduler menentukan **WHEN** evaluation dilakukan. DecisionEngine menentukan **WHAT**. Netlink mempercepat reaction; polling/reconciliation mempertahankan correctness.

Current timing contract:

```text
MIN_INTERVAL = 2s
MAX_INTERVAL = 90s
UNPLUGGED_HEARTBEAT = 600s
UNPLUGGED_HEARTBEAT_NO_NETLINK = 30s
```

Angka tersebut harus diperlakukan sebagai bounded scheduling policy dan diuji terhadap power budget.

## 2. Evaluation triggers

```text
startup
 ↓
periodic deadline
 ↓
power_supply netlink event
 ↓
debounce
 ↓
fresh snapshot
 ↓
policy
```

Event tidak boleh langsung melakukan hardware mutation dari netlink handler.

## 3. Netlink debounce

Current debounce sekitar 250ms masuk akal untuk menggabungkan burst uevent. Flow:

```text
event #1 → deadline=t+250ms
event #2 → keep/coalesce
...
deadline → one evaluation
```

100 uevent tidak boleh menjadi 100 `set_charging()`.

## 4. Netlink reconnect

Reconnect menggunakan bounded backoff:

```text
1s → 2s → ... → 60s
```

Jika reconnect sukses, backoff reset. Failure tidak boleh menghentikan periodic evaluation.

## 5. Polling fallback

Netlink bukan source of correctness. Jika socket mati:

```text
netlink unavailable
 → periodic snapshot remains active
 → state eventually reconciles
```

Heartbeat unplugged tanpa netlink harus cukup untuk mendeteksi reconnect.

## 6. Scheduler state

Scheduler boleh menyimpan:

```text
next_evaluation
next_netlink_deadline
next_reconnect
next_hardware_retry
next_verification
```

Tetapi scheduler tidak boleh menyimpan policy truth yang dapat bertentangan dengan DecisionEngine.

## 7. EMA

Current tuning concept:

```text
HISTORY_LEN = 6
EMA_ALPHA = 0.35
SAFETY_FACTOR = 0.25
THERMAL_SAFETY_FACTOR = 0.15
```

EMA hanya optimisasi ETA/scheduling. Ia bukan bukti bahwa threshold aman.

Validasi sample:

```text
dt > 0
rate finite
capacity delta plausible
sample age acceptable
```

Reject/reset jika sample mengalami discontinuity.

## 8. EMA reset conditions

Reset ketika:

```text
unplug/replug
long suspend
clock discontinuity
sensor invalid
capacity jumps implausibly
configuration changes relevant to model
battery/source identity changes
```

Jangan membawa rate lama ke sesi charging baru.

## 9. Thermal prediction

Prediction thermal hanya menentukan kapan scheduler boleh bangun lagi. Actual temperature threshold tetap dievaluasi oleh policy.

Jika prediction gagal:

```text
prediction invalid
 → conservative next wake
 → actual thermal check tetap aktif
```

Bukan:

```text
prediction invalid → thermal disabled
```

## 10. Retry integration

Hardware retry deadline harus menjadi salah satu candidate wake time. Jangan membuat scheduler sendiri melakukan retry write.

```text
next_wake = min(
  policy_deadline,
  netlink_deadline,
  verification_deadline,
  retry_deadline,
  heartbeat
)
```

Semua menggunakan monotonic time.

## 11. Race: event vs timer

Jika timer dan netlink event datang bersamaan:

```text
coalesce → one evaluation
```

Fresh snapshot digunakan sekali untuk decision. Setelah decision berubah target, controller mengatur operation.

## 12. Stale event

Event tidak membawa snapshot value yang dianggap authoritative. Event hanya trigger untuk read fresh state. Dengan begitu event yang terlambat tidak dapat menimpa snapshot baru.

## 13. Testing

```text
[ ] no netlink
[ ] reconnect success/failure
[ ] burst 100 events
[ ] timer + event simultaneous
[ ] debounce boundary
[ ] unplug heartbeat
[ ] EMA normal
[ ] EMA dt=0
[ ] EMA negative/discontinuous
[ ] long suspend
[ ] sensor invalid
[ ] retry deadline
[ ] thermal prediction invalid
```

## 14. Acceptance criteria

1. Scheduler tidak menentukan charging target.
2. Netlink failure tidak mematikan correctness.
3. Event storm dicoalesce.
4. Snapshot selalu fresh setelah relevant event.
5. EMA tidak mempengaruhi safety decision.
6. Semua deadlines monotonic.
7. Idle wakeup dan sysfs-read budget dapat diukur.
