# 21 — Error Taxonomy & Recovery Policy

## Invariant
- **I-ERR-001**: error type menentukan severity dan recovery.
- **I-ERR-002**: `Unknown != Offline != Fault`.
- **I-ERR-003**: retry hanya untuk error yang retryable.
- **I-ERR-004**: safety failure lebih prioritas daripada availability.

## Taxonomy
```text
ParseError       -> bad input, no retry
Unsupported      -> capability absent, usually no retry
TransientIo      -> retry with backoff
PermissionDenied -> configuration/deployment fault
InvalidHardware  -> safe state + operator attention
VerificationFail-> reconcile/retry, then bounded backoff
PersistenceError -> fail-safe, do not claim committed state
ProtocolError    -> reject request
InternalBug      -> fail closed + diagnostic
```

## Unknown semantics
Sensor unavailable bukan berarti device unplugged. `Offline` hanya jika evidence power source memang offline. `Fault` membutuhkan evidence bahwa sistem tidak dapat beroperasi sesuai safety contract.

## Backoff
Retry harus bounded dan jitter dapat ditambahkan bila ada banyak event. Reset failure counter hanya setelah successful operation + verification, bukan hanya successful write.

## Observability
Setiap error minimal memiliki category, operation ID, capability, attempt, retry_at, dan sanitized cause.

## Acceptance criteria
1. Setiap error controller dipetakan ke retry policy.
2. Unknown sensor tidak memicu disable/enable secara salah.
3. Verification failure tidak langsung menjadi permanent fault.
4. Permanent fault dapat didiagnosis tanpa reproduksi langsung.
