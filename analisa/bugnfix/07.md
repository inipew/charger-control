# 07 — Daemon Runtime & IPC

## Masalah utama
Runtime harus menjadi satu-satunya orchestrator. IPC, signal, dan netlink tidak boleh memiliki lifecycle/hardware state sendiri.

## Event model
```text
SensorChanged
TimerExpired
HardwareRetryDue
VerificationDue
ConfigReload
ManualCommand
ShutdownRequested
NetlinkFailure
```

Semua event masuk ke event loop/monitor dan diproses serial.

## Shutdown P0
Tidak boleh ada:
```rust
process::exit(0)
```
dari IPC worker. Worker hanya mengirim `ShutdownRequested` lalu return.

Single sequence:
```text
stop new work
 → restore ownership
 → verify
 → persist
 → close IPC
 → exit
```
SIGTERM/SIGINT harus memakai sequence yang sama.

## IPC boundary
IPC melakukan:
```text
accept
 → authenticate/authorize
 → parse bounded request
 → send event
 → return response
```
Bukan hardware write.

## Security
Socket tidak boleh world-writable. Mutation commands harus authorization-gated. Request length, read/write timeout, concurrent clients, dan response size harus bounded.

## Netlink
Netlink hanya menghasilkan `SensorChanged`/reconciliation trigger. Jika netlink hilang, scheduler polling tetap menjamin correctness.

## Threading
Idealnya hanya runtime thread yang memutasi controller. Worker IPC/signal hanya producer event.

## Acceptance criteria
- shutdown integration test;
- SIGTERM/SIGINT equivalence;
- unauthorized IPC rejected;
- malformed/oversized request rejected;
- netlink failure falls back to polling;
- no hardware write from IPC thread.
