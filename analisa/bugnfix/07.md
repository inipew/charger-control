# 07 — Daemon Runtime & IPC

## 1. Runtime contract

Runtime adalah orchestrator tunggal. Semua input eksternal diubah menjadi event, lalu diproses secara serial:

```text
IPC / Signal / Netlink / Timer
            ↓
        Event Queue
            ↓
       Runtime Loop
      ┌─────┴─────┐
   Snapshot     Command
      ↓             ↓
    Policy       Mode/Config
      └─────┬─────┘
            ↓
       HardwareController
```

Tujuannya menghilangkan dua actor userspace yang dapat menulis hardware secara bersamaan.

## 2. Event taxonomy

Minimal:

```text
Evaluate
TimerExpired
SensorChanged
VerificationDue
HardwareRetryDue
ConfigReload
ManualCommand
ShutdownRequested
NetlinkFailure
```

Event harus membawa correlation ID bila berasal dari request. Netlink event boleh dicoalesce.

## 3. IPC flow

```text
accept
 ↓
peer credential / permission check
 ↓
bounded frame read
 ↓
protocol/version validation
 ↓
authorization
 ↓
convert request → event
 ↓
runtime processing
 ↓
bounded response
```

IPC tidak boleh memanggil `control::set_charging()`.

## 4. Shutdown P0

Jangan melakukan:

```rust
process::exit(0);
```

dari IPC worker. Itu dapat memotong cleanup runtime.

Canonical sequence:

```text
ShutdownRequested
 → mark shutting_down
 → reject new mutating commands
 → finish/cancel current evaluation at safe boundary
 → controller shutdown/release transaction
 → verify required final state
 → persist final state
 → close socket
 → join workers
 → exit
```

SIGTERM, SIGINT, dan IPC shutdown harus masuk sequence yang sama.

## 5. Shutdown race

Kasus:

```text
T0: policy decides ON
T1: IPC requests shutdown
T2: stale evaluation tries ON
```

Setelah `shutting_down=true`, T2 harus ditolak. Shutdown flag harus dicek di boundary sebelum mutation.

## 6. IPC authorization

Socket mode `0666` tidak cocok untuk root charging controller. Recommended:

```text
socket dir: 0750/0700
socket: 0660
owner: root
restricted group
```

Untuk command sensitif, credential/command policy tetap diperlukan.

## 7. Bounded resources

Batasi:

```text
max frame size
max arguments
max concurrent clients
read timeout
write timeout
max response
```

Malformed input tidak boleh menyebabkan blocking tanpa batas atau memory allocation besar.

## 8. Manual commands

Manual enable/disable/bypass harus menjadi typed command:

```text
ManualSetTarget(ChargingEnabled)
ManualSetTarget(ChargingDisabled)
SetMode(Unmanaged)
```

Runtime meneruskannya ke controller. Tidak boleh ada arbitrary path/value IPC API.

## 9. Netlink integration

Netlink hanya mempercepat evaluation. Event:

```text
SUBSYSTEM=power_supply
ACTION=change
```

dapat menjadi `SensorChanged`, dengan debounce. Jika netlink socket gagal:

```text
NetlinkFailure
 → reconnect backoff
 → polling remains active
```

## 10. Worker model

Worker boleh melakukan blocking accept/read, tetapi hardware controller sebaiknya dimiliki satu runtime executor. Jika worker perlu response sinkron, gunakan request channel + response channel, bukan direct controller reference.

## 11. Error propagation

IPC harus dapat membedakan:

```text
Accepted
RejectedUnauthorized
InvalidRequest
Busy
TimedOut
HardwareFailed
VerificationFailed
ShuttingDown
```

Jangan mengembalikan `200/OK` style success jika operation hanya queued; bedakan `accepted` dari `verified`.

## 12. Testing

```text
[ ] two simultaneous clients
[ ] unauthorized client
[ ] malformed frame
[ ] oversized frame
[ ] slow client
[ ] client disconnect mid-request
[ ] shutdown during evaluation
[ ] shutdown during verification
[ ] SIGTERM during hardware apply
[ ] SIGINT same path
[ ] netlink unavailable
[ ] event storm
[ ] manual command racing timer
```

Integration test harus membuktikan tidak ada write setelah shutdown gate aktif.

## 13. Acceptance criteria

1. Runtime adalah single orchestrator.
2. IPC tidak melakukan hardware mutation.
3. Shutdown hanya mempunyai satu path.
4. Privileged commands terotorisasi.
5. Resource IPC bounded.
6. Netlink failure tidak mematikan correctness.
7. Queued/accepted tidak disamakan dengan verified hardware state.
