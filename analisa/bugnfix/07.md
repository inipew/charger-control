# 07 — DAEMON RUNTIME, EVENT LOOP & IPC

## Runtime architecture

```text
IPC ─────┐
Netlink ─┼→ DaemonEvent → serialized monitor/runtime
Signal ──┤                         ↓
Timer ───┘                    Policy
                                  ↓
                               Intent
                                  ↓
                           HardwareController
```

Hanya runtime owner yang boleh mengubah mutable daemon state.

## Event model

```rust
enum DaemonEvent {
    SensorChanged,
    TimerExpired,
    HardwareVerificationDue,
    HardwareRetryDue,
    ConfigReload,
    ManualCommand,
    ShutdownRequested,
    NetlinkFailure,
}
```

Adapter event tidak boleh melakukan hardware mutation langsung.

## IPC protocol

Request minimal:

```text
version
request_id
command
payload
```

Response:

```text
version
request_id
status
error_code
message
```

Harus ada batas ukuran request, timeout, dan penolakan protocol version yang tidak didukung.

## Authorization

Pisahkan capability read-only dan mutation:

```text
ReadStatus
ReadConfig
ChangePolicy
ChangeHardware
Shutdown
```

Socket permission adalah lapisan pertama; authorization command adalah lapisan kedua.

## IPC lifecycle

Client disconnect tidak boleh membuat daemon crash atau meninggalkan operation setengah jalan.

Semua read/write harus memiliki bounded timeout dan error handling eksplisit.

## Shutdown

Satu fungsi authoritative:

```text
shutdown_sequence()
```

Dipanggil melalui event yang berasal dari:

```text
SIGTERM
SIGINT
IPC shutdown
internal fatal shutdown
```

Sequence:

```text
freeze new mutations
→ cancel retry
→ restore ownership
→ verify
→ preserve unresolved ownership if failure
→ close IPC/netlink
→ exit from lifecycle owner
```

Tidak boleh `process::exit()` dari worker IPC.

## poll()

Semantics wajib:

```text
ret > 0 → event
ret == 0 → timeout
ret < 0 → error
```

`EINTR` ditangani secara eksplisit. Periksa:

```text
POLLIN
POLLERR
POLLHUP
POLLNVAL
```

## Netlink

Netlink adalah accelerator.

```text
uevent
→ invalidate/re-read
→ evaluate
```

Bukan:

```text
uevent
→ assume final state
```

Reconnect menggunakan satu fungsi retry/backoff agar tidak ada dua sumber perubahan `reconnect_at`/backoff.

## Resource lifecycle

Gunakan RAII (`OwnedFd` atau wrapper) untuk descriptor. Hindari manual `RawFd` lifecycle jika tidak diperlukan.

## Serialized mutations

Tidak boleh ada:

```text
IPC thread → sysfs
Netlink thread → sysfs
Timer thread → sysfs
```

Semua mutation masuk satu execution boundary.

## Acceptance

Runtime harus tetap aman jika:

- client mengirim request malformed;
- client disconnect;
- socket error;
- Netlink hilang;
- signal datang saat verification;
- shutdown datang saat retry;
- dua command mutation datang bersamaan.
