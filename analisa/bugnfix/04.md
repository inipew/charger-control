# 04 — HARDWARE CONTROL, CAPABILITY & VERIFICATION

## Tujuan

Membuat boundary hardware deterministic dan vendor-aware tanpa mencampur hardware I/O dengan policy.

## Layer

```text
HardwareProfile
    ↓
HardwareCapabilities
    ↓
HardwareController
    ↓
HardwareIo
    ↓
/sys/class/power_supply
```

`HardwareProfile` mendeskripsikan node, capability, unit, sign convention, priority, required/optional, dan verification strategy. Profile tidak menentukan business policy.

## Capability model

```rust
struct HardwareCapabilities {
    charging_control: bool,
    input_suspend: bool,
    current_measurement: bool,
    temperature_measurement: bool,
}
```

Path yang ada tidak otomatis berarti capability aman untuk digunakan.

## Required vs optional node

Profile harus menentukan:

```text
required node failure → operation failure
optional node failure → diagnostic/degraded
```

Contoh:

```text
charging_enable → required
input_suspend   → optional
```

sesuai profile device.

## Hardware state

```rust
enum HardwareState {
    Unmanaged,
    Applying,
    Enabled,
    Disabled,
    Mixed,
    Unknown,
    Failed,
}
```

Jangan menyamakan `Mixed`, `Unknown`, dan `NoNode`.

## Semantic errors

```rust
enum HardwareStateError {
    NoNode,
    ReadFailed,
    WriteFailed,
    InvalidValue,
    MixedState,
    UnknownState,
}
```

Recovery tiap error berbeda.

## Transaction

### Apply

```text
read actual
→ persist ownership
→ write all required controls
→ read actual
→ verify
→ publish synced
```

### Partial failure

```text
node A OK
node B FAIL
    ↓
read A+B
    ↓
classify actual
    ↓
reconcile
    ↓
verify
```

Tidak boleh langsung menganggap target tercapai.

## Verification

Pisahkan:

```text
ControlState   = node control value
ElectricalState = charging/discharging/idle
SensorState    = valid/invalid
```

Current threshold bukan universal proof bahwa charging disabled. Threshold harus berasal dari profile atau menjadi secondary diagnostic.

## Generation

Setiap hardware intent mendapat generation/operation ID.

```text
intent G10
verification G10

intent berubah → G11

late verification G10 → ignore
```

Dengan ini completion lama tidak dapat menimpa state baru.

## HardwareIo

Core harus menggunakan trait:

```rust
trait HardwareIo {
    fn read(&self, path: &Path) -> Result<String, ChargerError>;
    fn write(&self, path: &Path, value: &str) -> Result<(), ChargerError>;
    fn exists(&self, path: &Path) -> bool;
}
```

Production adapter menggunakan sysfs. Test menggunakan mock/in-memory implementation.

## Resource ownership

Gunakan RAII (`OwnedFd` atau wrapper setara) untuk file/socket resource. Hindari lifecycle `RawFd` manual bila memungkinkan.

## Acceptance

Controller dianggap benar jika:

- tidak ada direct write dari IPC/CLI/policy;
- partial write terdeteksi;
- mixed/unknown dibedakan;
- verification wajib;
- late verification diabaikan;
- required/optional node semantics eksplisit;
- test tidak membutuhkan Android kernel nyata.
