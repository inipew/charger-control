# 04 — Hardware Control & Verification

## Temuan
HardwareController adalah boundary terpenting. Tidak boleh ada direct sysfs write dari IPC, CLI, policy, atau monitor.

## Target flow
```text
HardwareIntent
 ↓
Controller
 ↓ ownership prepare
 ↓ write nodes
 ↓ readback
 ↓ verify
 ↓ commit applied state
```

## Node model
Setiap node harus memiliki metadata:
```text
path
kind
priority
required
authoritative
value semantics
```

`required` menentukan kegagalan operation; `optional` hanya warning/degraded capability.

## Partial failure
Jika satu node gagal:
```text
partial write
 ↓
read all actual nodes
 ↓
classify Mixed/Unknown
 ↓
converge to safe target
 ↓
verify
```

Jangan menunggu retry timer sebagai recovery pertama.

## Verification
Pisahkan:
```text
control state
actual electrical state
sensor state
```

Control `Disabled` tidak universal berarti battery current harus <=100mA. Electrical evidence hanya secondary kecuali profile mendefinisikannya sebagai required proof.

## Retry
Retry hanya untuk transient failure. Backoff bounded. Counter reset hanya setelah apply + verification sukses.

## Generation
Pisahkan:
```text
intent_generation
operation_id
verification_generation
ownership_generation
```

## External mutation
Jika actual berbeda dari desired setelah sebelumnya verified:
```text
ExternalModification
 → reconciliation
 → bounded reapply
```

Repeated interference harus menghasilkan degraded/fault state, bukan infinite write fight.

## Acceptance criteria
1. Semua writes lewat controller.
2. Partial failure menghasilkan readback.
3. Mixed/Unknown dapat dibedakan.
4. Successful write tanpa verification tidak dilaporkan synced.
5. External mutation dapat direkonsiliasi.
