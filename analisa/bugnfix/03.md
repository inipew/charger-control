# 03 — Policy & State Machine

## Tujuan
DecisionEngine harus deterministik, tanpa I/O dan tanpa hidden side effect.

## State
```text
Disabled
Offline
Charging
LimitReached
ThermalCutoff
ManualBypass
Fault
```

Runtime/ownership/hardware state tetap dipisahkan dari policy state.

## Priority
```text
Shutdown
 > Recovery
 > Disabled
 > Hardware/Sensor Fault
 > Offline
 > ThermalProtection
 > ManualBypass
 > ChargeLimit
 > NormalCharging
```

Safety layer kernel/vendor selalu lebih tinggi daripada policy userspace.

## Charge-limit hysteresis
```text
Charging + capacity >= limit
    → LimitReached

LimitReached + capacity <= resume
    → Charging
```

Effective values harus sudah tervalidasi sebelum engine berjalan.

## Thermal
Jika `thermal_cutoff=false`, thermal transition tidak boleh terjadi. Jika enabled:

```text
temp >= max_temp
    → ThermalCutoff

temp <= max_temp - hysteresis
    → resume
```

Jangan mengaktifkan thermal policy hanya karena `max_temp_dc` terisi.

## Presence
```text
Online → charging policy eligible
Offline → no charging intent
Unknown → conservative; jangan menyimpulkan unplugged
```

## Fault
Required sensor/hardware evidence invalid dapat masuk Fault. Recovery membutuhkan N snapshot valid berturut-turut sesuai konfigurasi, lalu engine mengevaluasi ulang; jangan auto-recover hanya karena satu read sukses.

## Determinism
Input engine minimal:
```text
ConfigSnapshot
SensorSnapshot
CurrentMode
PreviousPolicyState
```
Output:
```text
PolicyState
HardwareIntent
DecisionReason
```

Tidak boleh membaca sysfs, clock global, filesystem, atau IPC dari engine.

## Acceptance tests
- semua boundary capacity;
- hysteresis tepat di threshold;
- thermal disabled/enabled;
- Unknown presence;
- fault recovery;
- manual bypass priority;
- repeated identical snapshot menghasilkan keputusan sama.
