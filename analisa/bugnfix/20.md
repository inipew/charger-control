# 20 — Persistence & Filesystem Integrity

## Tujuan
Ownership dan konfigurasi harus survive crash tanpa menghasilkan state palsu.

## Invariant
- **I-PERSIST-001**: persistence state memiliki schema/version.
- **I-PERSIST-002**: write atomic; partial file tidak dianggap committed state.
- **I-PERSIST-003**: crash di setiap phase operasi memiliki recovery rule.
- **I-PERSIST-004**: corrupted state tidak boleh diperlakukan sebagai valid ownership.

## Atomic update
Untuk file penting:
```text
write temp
 -> flush/fsync file
 -> atomic rename
 -> fsync parent directory bila diperlukan
```

Temp file harus memiliki permission yang benar sejak dibuat. Stale temp file tidak boleh dianggap current state.

## Journal
Ownership sebaiknya menyimpan phase seperti:
```text
Idle
AcquirePrepared
OwnershipAcquired
ApplyInProgress
Applied
ReleaseInProgress
```

Setiap record memiliki schema version, operation ID, timestamp/monotonic metadata yang relevan, dan data minimum untuk recovery.

## Corruption
Checksum dapat digunakan untuk mendeteksi silent corruption. Jika state invalid, daemon harus memilih safe recovery path; jangan langsung menghapus state tanpa mencoba memahami apakah hardware masih controlled.

## Acceptance criteria
1. Kill -9 di setiap titik transaksi menghasilkan recovery deterministik.
2. File hasil crash tidak pernah dibaca sebagai committed state parsial.
3. Schema lama ditangani migration atau explicit incompatibility.
4. Permission file/directory diuji.
