# 20 — Persistence & Filesystem Integrity

## 1. Scope

Persistence adalah safety mechanism. Ownership/config state yang rusak dapat membuat daemon salah memahami siapa yang terakhir mengontrol hardware.

## 2. Durable update

Canonical file update:

```text
serialize
 ↓
write temp in same directory
 ↓
flush/fsync temp
 ↓
atomic rename
 ↓
fsync parent directory
```

File lama tetap valid sampai rename berhasil.

## 3. Journal schema

Record minimal:

```text
schema_version
operation_id
intent_generation
phase
requested_target
original_state
node results
error
```

Jangan menyimpan data yang tidak diperlukan untuk recovery.

## 4. Phase semantics

```text
Prepared
 → Applying
 → Applied
 → Verifying
 → Committed
```

Release:

```text
ReleasePrepared
 → Restoring
 → RestoreVerified
 → Released
```

## 5. Crash behaviour

Crash di setiap phase harus memiliki recovery rule. Contoh `Applying` berarti startup wajib membaca actual state; tidak boleh diasumsikan sukses/gagal tanpa evidence.

## 6. Corruption

Detect:

```text
empty
truncated
bad syntax
unknown schema
checksum mismatch
invalid enum
```

Corrupt state tidak boleh otomatis dihapus lalu dianggap clean.

## 7. Permissions

Runtime directory, config, journal, temp files, lock, dan socket harus dibuat dengan mode yang tepat sejak awal. Jangan membuat world-writable lalu memperbaikinya kemudian.

## 8. Symlink/TOCTOU

State file berada di trusted directory. Creation/replacement harus mencegah symlink redirection bila threat model membutuhkan.

## 9. Migration

Schema migration harus explicit:

```text
old supported → migrate → validate → atomically commit
unknown/unsafe → reject
```

## 10. Testing

```text
[ ] crash before write
[ ] crash after temp write
[ ] crash before rename
[ ] crash after rename
[ ] truncated journal
[ ] wrong checksum
[ ] old schema
[ ] unknown schema
[ ] permission denied
[ ] symlink attack
```

## 11. Acceptance criteria

1. Partial persistence tidak terlihat sebagai committed state.
2. Crash recovery deterministic.
3. Corruption terdeteksi.
4. Schema versioned.
5. Permissions restrictive.
6. Recovery evidence tidak hilang karena cleanup otomatis.
