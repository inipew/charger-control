# 23 — Configuration Semantics

## Invariant
- **I-CFG-001**: schema, validation, normalization, dan persistence memiliki satu source of truth.
- **I-CFG-002**: malformed config tidak boleh diam-diam diganti default.
- **I-CFG-003**: default hanya berlaku untuk missing field/file yang memang diizinkan.
- **I-CFG-004**: reload bersifat transactional.

## Pipeline
```text
Read bytes
 -> Parse
 -> Schema/version check
 -> Validate
 -> Normalize
 -> Build runtime config
 -> Commit atomically
```

`normalize()` boleh mengisi nilai yang memang semantically equivalent, tetapi tidak boleh menyembunyikan konfigurasi invalid.

## Reload
Config baru divalidasi penuh sebelum menggantikan config lama. Jika gagal, config aktif tetap digunakan dan client menerima error yang jelas.

Jika perubahan menyentuh capability/profile atau safety threshold, reload harus menentukan apakah perlu reconciliation segera.

## Persistence
Gunakan atomic write. Jangan `unwrap_or_default()` pada error I/O/parse yang berpotensi menimpa config pengguna.

## Versioning
Tambahkan `config_version` dan migration strategy. Config yang tidak dikenal versinya harus ditolak atau dimigrasikan secara eksplisit.

## Acceptance criteria
1. TOML rusak tidak menimpa config valid.
2. CLI dan file config menghasilkan validation result identik.
3. Reload gagal tidak mengubah runtime config.
4. Config version lama punya migration test.
