# 12 — IMPLEMENTATION ROADMAP & DEFINITION OF DONE

## Urutan implementasi

Dokumen ini menjadi urutan eksekusi agar refactor tidak dilakukan secara acak.

### Phase 0 — Baseline

```text
format/check/test/clippy
→ record current failures
→ freeze semantics
```

### Phase 1 — P0 safety

1. Satukan shutdown path.
2. Hilangkan `process::exit()` dari worker IPC.
3. Pastikan thermal switch authoritative.
4. Pindahkan bypass ke controller.
5. Secure IPC.
6. Hentikan corrupt-config fallback.
7. Centralize config validation.

### Phase 2 — Hardware correctness

1. Semantic hardware errors.
2. Required/optional node semantics.
3. `HardwareIntent`.
4. Partial-write reconciliation.
5. Generation-aware verification.
6. Explicit control/electrical/sensor states.

### Phase 3 — Ownership

1. Journal version.
2. Atomic persistence.
3. Explicit phases.
4. Crash recovery.
5. Corrupt ownership handling.
6. Recovery tests.

### Phase 4 — Sensor/readers

1. Canonical `BatteryReader`.
2. Profile-driven paths.
3. Sensor sanity validation.
4. Cached FD rescan.
5. Explicit online-node priority.
6. Current sign/unit normalization.

### Phase 5 — Runtime

1. Serialized `DaemonEvent` loop.
2. IPC request/response protocol.
3. Signal adapter.
4. Netlink adapter.
5. Controller deadlines.
6. RAII resources.

### Phase 6 — Scheduler

1. Separate actual charging from policy state.
2. Deadline-driven wakeups.
3. Conservative fallback.
4. EMA plausibility filter.
5. Reset EMA on relevant discontinuities.
6. Remove unnecessary periodic wakeups.

### Phase 7 — Observability

Expose:

```text
DaemonStatus
ControllerEvent
operation_id
correlation_id
metrics
structured logs
```

### Phase 8 — Testing

1. Unit tests.
2. Invariant tests.
3. Fault injection.
4. Fake clock.
5. Property tests.
6. Integration tests.
7. Android hardware tests.

## Final architecture

```text
                  Android Kernel
                 /              \
              Sysfs           Netlink
                │                 │
           HardwareIo        NetlinkAdapter
                │                 │
                ▼                 ▼
        HardwareController ← DaemonEvent
                ▲                 ▲
                │                 │
             Intent            Runtime
                ▲                 ▲
                │                 │
             Policy       IPC / Signal / Timer
                ▲
                │
        SensorSnapshot + Config
```

Persistence/ownership menjadi cross-cutting infrastructure, tetapi hardware mutation tetap hanya melalui controller.

## Definition of Done

### Architecture

- [ ] Policy pure dan testable.
- [ ] Scheduler tidak menentukan policy.
- [ ] Controller satu-satunya hardware writer.
- [ ] HardwareIo menjadi I/O boundary.
- [ ] Persistence tidak bercampur dengan policy.

### Safety

- [ ] Unknown first-class.
- [ ] Sensor failure tidak menjadi zero/default.
- [ ] Thermal cutoff authoritative.
- [ ] Verification wajib.
- [ ] Partial write direkonsiliasi.

### Recovery

- [ ] Ownership atomic.
- [ ] Crash recovery deterministic.
- [ ] Corrupt journal tidak dihapus otomatis.
- [ ] Shutdown restore verified.

### Runtime

- [ ] IPC secure.
- [ ] Protocol bounded.
- [ ] Shutdown satu path.
- [ ] Netlink failure safe.
- [ ] FD lifecycle RAII.

### Testing

- [ ] Invariant tests.
- [ ] Fault injection.
- [ ] Fake clock.
- [ ] Property/state-machine tests.
- [ ] Integration recovery.
- [ ] Android real-device tests.

## Release criterion

ChargerControl baru boleh disebut **production-ready** jika semua item safety dan recovery selesai, test suite relevan lulus, dan behaviour telah diverifikasi pada device/kernel Android target.
