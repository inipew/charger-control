# 19 — Security Threat Model

## 1. Scope

Daemon memiliki privilege tinggi dan dapat mengubah charging hardware. Local Unix IPC karena itu harus diperlakukan sebagai security boundary, walaupun hanya tersedia di device sendiri.

## 2. Assets

```text
charging control authority
config integrity
ownership/recovery state
runtime availability
diagnostic integrity
```

## 3. Attack surfaces

```text
Unix socket
CLI arguments
config files
ownership journal
profile paths
log fields
IPC framing
local process flooding
```

## 4. IPC authorization

Minimum:

```text
trusted socket directory
socket 0660
owner/group restriction
command allowlist
credential authorization
protocol version
bounded frame
read/write timeout
```

Read-only status dapat memiliki policy berbeda dari mutation/shutdown.

## 5. No arbitrary hardware path

Request tidak boleh berisi:

```text
path=/sys/.../some_node
value=1
```

API harus semantic:

```text
SetTarget(ChargingEnabled)
SetTarget(ChargingDisabled)
SetMode(Unmanaged)
```

Path dan value ditentukan oleh trusted capability/profile layer.

## 6. Filesystem security

Config, journal, socket, dan lock berada pada trusted directory dengan permission restrictive. Hindari symlink/TOCTOU ketika membuat atau mengganti file.

## 7. Input bounds

Batasi:

```text
frame bytes
argument count
string length
client count
queue depth
processing time
response size
log field length
```

Fuzz input tidak boleh panic atau menyebabkan unbounded allocation.

## 8. DoS

Slow client tidak boleh menahan runtime. Satu client disconnect harus membebaskan resource. Queue penuh harus menghasilkan `Busy`/backpressure, bukan memory growth tak terbatas.

## 9. Log injection

External strings harus di-structure dan dibatasi panjangnya. Jangan membiarkan control characters merusak log stream.

## 10. Secret/data minimization

Jangan log raw credentials, private filesystem content, atau arbitrary request payload jika tidak diperlukan. Hardware paths dapat dibatasi pada identifiers profile.

## 11. Security failure policy

Unauthorized mutation harus ditolak sebelum mencapai controller. Invalid protocol tidak boleh menghasilkan partial hardware action.

## 12. Testing

```text
[ ] wrong uid
[ ] wrong group
[ ] unauthorized command
[ ] oversized frame
[ ] malformed frame
[ ] slow client
[ ] concurrent clients
[ ] queue exhaustion
[ ] arbitrary path injection
[ ] profile injection
[ ] symlink state-file attack
[ ] log injection
[ ] fuzz parser
```

## 13. Acceptance criteria

1. Unprivileged local process tidak dapat mutation.
2. Tidak ada arbitrary hardware path API.
3. Input/resource bounded.
4. Security failure tidak menyentuh hardware.
5. Filesystem state protected.
6. Fuzzing tidak menemukan panic/security boundary bypass.
