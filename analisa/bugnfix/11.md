# 11 — Android / Vendor / Magisk

## Real platform boundary
Linux power-supply semantics tidak identik antar vendor. Property dapat tidak tersedia; control node, sign current, topology, dan external actors berbeda.

## Magisk lifecycle
Boot script harus ringan dan non-blocking. Daemon harus menjadi process yang jelas, memiliki single-instance lock, dan tidak meninggalkan process lama saat update/disable.

## Vendor actors
Anggap mungkin ada:
```text
Android framework
vendor HAL/daemon
thermal service
charger driver
other root module
user tools
```

Karena itu ownership bukan hak absolut atas sysfs. External mutation harus terdeteksi dan dibatasi retry-nya.

## SELinux
Deployment harus mendokumentasikan:
```text
required file access
socket access
sysfs access
process transition
```
Jangan menyelesaikan SELinux issue dengan policy luas tanpa capability justification.

## Power-supply compatibility
Profile harus menjelaskan required/optional properties dan control semantics. Generic profile harus conservative.

## Boot order
```text
Magisk service
 → daemon start
 → lock
 → config
 → profile/capability probe
 → ownership recovery
 → snapshot baseline
 → policy
```

## Uninstall/disable
```text
shutdown request
 → restore owned hardware
 → verify
 → stop process
 → verify process stopped
 → disable/remove
```

## Acceptance criteria
1. Tested pada boot/reboot/disable/update.
2. Tidak ada double daemon.
3. SELinux denials teridentifikasi secara eksplisit.
4. External vendor actor tidak menyebabkan infinite write fight.
5. Device tanpa required capability masuk safe degraded mode.
