# 24 — CLI & IPC API Contract

## Tujuan
CLI dan IPC harus menjadi API yang versioned, deterministic, dan aman.

## Invariant
- **I-API-001**: protocol memiliki version.
- **I-API-002**: mutation command idempotent atau memiliki request ID.
- **I-API-003**: timeout dan response size bounded.
- **I-API-004**: CLI tidak boleh bypass controller/ownership.
- **I-API-005**: exit code memiliki makna stabil.

## Command classes
```text
Read-only: status, capabilities, diagnostics
Control: enable, disable, reload
Lifecycle: shutdown
Recovery: reconcile, clear-stale-state (restricted)
```

Semua mutation masuk melalui runtime/controller yang sama dengan monitor normal.

## Request contract
Request sebaiknya memiliki:
- protocol version;
- request ID;
- command;
- optional arguments yang typed;
- deadline/timeout bila diperlukan.

Response:
- success/failure;
- stable error code;
- operation ID jika mutation asynchronous;
- current status snapshot bila aman.

## Idempotency
`enable` ketika sudah enabled harus menjadi no-op terverifikasi, bukan write berulang. `shutdown` kedua kali harus predictable.

## Acceptance criteria
1. Client dengan protocol version unsupported ditolak dengan error stabil.
2. Malformed request tidak panic.
3. CLI dan IPC memakai service layer yang sama.
4. Exit code terdokumentasi dan dites.
5. Restricted recovery command membutuhkan authorization.
