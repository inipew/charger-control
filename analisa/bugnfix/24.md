# 24 — CLI & IPC API Contract

## 1. API principle

CLI adalah client; daemon adalah authority. Tidak boleh ada dua implementasi controller yang memiliki semantics berbeda.

```text
charger-ctl
 → IPC protocol
 → runtime service
 → controller
 → hardware
```

## 2. Command classes

```text
Read-only: status/capabilities/diagnostics
Control: enable/disable/reload
Lifecycle: shutdown
Recovery: reconcile/recovery diagnostics
```

Recovery commands yang dapat mutation harus restricted.

## 3. Request envelope

Minimal:

```text
protocol_version
request_id
command
typed arguments
timeout/deadline
```

Request ID digunakan untuk correlation/idempotency.

## 4. Response envelope

```text
status
stable error code
request_id
operation_id (mutation)
optional state snapshot
```

Bedakan:

```text
Accepted
Applied
Verified
Failed
TimedOut
```

## 5. Idempotency

Contoh `enable` saat sudah verified:

```text
request enable
 → actual already matches
 → no redundant write
 → Verified/no-op
```

Repeated shutdown harus predictable dan tidak melakukan mutation kedua.

## 6. Timeout

Timeout client tidak boleh otomatis membatalkan hardware operation tanpa protocol semantics. Setelah timeout client, daemon tetap dapat menyelesaikan operation dan status dapat diperiksa menggunakan request/operation ID.

## 7. Protocol compatibility

Unsupported protocol version harus ditolak sebelum mutation. Tambahkan compatibility policy untuk minor/major version.

## 8. Security

Command authorization dilakukan sebelum controller. Client tidak boleh mengirim arbitrary sysfs path/value.

## 9. Testing

```text
[ ] valid request
[ ] unsupported version
[ ] malformed frame
[ ] duplicate request_id
[ ] timeout
[ ] client disconnect
[ ] repeated enable
[ ] repeated disable
[ ] repeated shutdown
[ ] unauthorized recovery
```

## 10. Acceptance criteria

1. CLI dan daemon memakai semantics yang sama.
2. Protocol versioned.
3. Mutation memiliki operation ID.
4. Idempotency predictable.
5. Timeout tidak false-report failure.
6. Unsupported/malformed request tidak menyentuh hardware.
