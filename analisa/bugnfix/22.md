# 22 — Temporal Correctness

## Masalah
Daemon charging adalah sistem temporal: event dapat terlambat, snapshot dapat stale, dan beberapa keputusan dapat bersaing.

## Invariant
- **I-TIME-001**: deadline/retry/snapshot age memakai monotonic clock.
- **I-TIME-002**: wall clock hanya untuk human-facing timestamps/logging.
- **I-TIME-003**: stale event tidak boleh mengalahkan state yang lebih baru.
- **I-TIME-004**: satu operation memiliki unique operation ID.

## Ordering
Gunakan sequence/generation untuk membedakan:
- intent generation;
- hardware operation ID;
- ownership generation;
- verification generation;
- event sequence bila source menyediakan ordering.

Jangan memakai satu integer `generation` untuk semua makna.

## Staleness
Snapshot memiliki `captured_at` monotonic dan age. Policy dapat menolak snapshot yang terlalu tua. Nilai stale tidak boleh digunakan sebagai evidence safety tanpa aturan eksplisit.

## Debounce
Debounce/coalescing event harus mempertahankan invariant final state. Event storm boleh menghasilkan satu reconciliation, bukan satu write per event.

## Acceptance criteria
1. Test event A/B out-of-order tidak menyebabkan rollback state.
2. Snapshot stale ditolak sesuai threshold.
3. Clock adjustment wall-time tidak mempengaruhi retry.
4. Operation ID dapat ditelusuri dari intent sampai verification.
