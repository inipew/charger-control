# 22 — Temporal Correctness

## 1. Tujuan

Daemon harus benar bukan hanya terhadap value, tetapi juga terhadap **kapan** value/event terjadi. Race, stale snapshot, suspend, dan delayed verification adalah bagian dari normal Android behaviour.

## 2. Clock model

Gunakan monotonic time untuk:

```text
retry_at
verification deadline
debounce
scheduler deadline
snapshot age
operation timeout
```

Wall clock hanya untuk human-readable timestamps. Perubahan wall clock tidak boleh mempercepat/menghentikan retry.

## 3. Identity model

Pisahkan:

```text
intent_generation
operation_id
ownership_generation
verification_generation
event sequence
```

Satu integer tidak boleh mewakili semuanya.

## 4. Out-of-order event

```text
event A → state version 10
event B → state version 11
event A processed late
```

A tidak boleh rollback state 11. Netlink event umumnya trigger fresh read, bukan authoritative state payload.

## 5. Snapshot staleness

Snapshot harus memiliki capture time. Jika age melebihi safety threshold:

```text
stale
 → cannot prove current safety
 → fresh read/reconciliation
```

Cache tidak boleh menjadi proof hanya karena read operation terakhir sukses.

## 6. Verification timing

Verification window harus bounded dan operation-specific. Readback dari operation lama tidak boleh commit operation baru.

## 7. Debounce

Debounce hanya mengurangi evaluation frequency. Ia tidak boleh menunda safety response melebihi batas yang diterima policy.

## 8. Suspend

Setelah resume, missed deadlines tidak direplay satu per satu. Lakukan satu reconciliation dengan current snapshot/actual hardware.

## 9. Race example

```text
T0 desired OFF
T1 apply OFF
T2 desired ON
T3 late OFF verification succeeds
```

Verification T3 harus ditolak jika operation ID/generation tidak lagi current.

## 10. Testing

```text
[ ] wall-clock jump
[ ] monotonic progression
[ ] stale snapshot
[ ] event out of order
[ ] verification result late
[ ] desired change mid-operation
[ ] debounce storm
[ ] suspend/resume
[ ] retry deadline during suspend
```

## 11. Acceptance criteria

1. Wall clock tidak mempengaruhi deadlines.
2. Late result tidak mengalahkan intent baru.
3. Snapshot age terukur.
4. Event hanya trigger fresh evidence.
5. Suspend tidak membuat backlog mutation.
6. Operation identity dapat ditelusuri end-to-end.
