# 02 — ARCHITECTURE INVARIANTS

Dokumen ini mendefinisikan hukum arsitektur yang tidak boleh dilanggar oleh implementasi maupun refactor berikutnya.

## A. Hardware ownership

### I-001 — Single hardware writer
Hanya `HardwareController` yang boleh melakukan mutation terhadap charging-control nodes.

```text
IPC / CLI / Netlink / Timer
          ↓
        Event
          ↓
        Policy
          ↓
        Intent
          ↓
 HardwareController
          ↓
     HardwareIo
          ↓
        sysfs
```

### I-002 — Ownership before mutation
Tidak ada controlled mutation sebelum original hardware state berhasil dibaca dan ownership record berhasil dipersist.

### I-003 — No false success
Operasi hardware hanya sukses setelah seluruh required nodes berhasil ditulis dan verification berhasil.

### I-004 — Partial write != success
Partial write selalu menghasilkan `Unknown/Mixed/Failed`, lalu reconciliation.

### I-005 — Verification failure invalidates sync
`Synced + verification failed` wajib berubah menjadi `Unsynced/Unknown`.

## B. State semantics

### I-006 — Unknown is first-class
`Unknown` tidak boleh dikonversi menjadi `Offline`, `Disabled`, `0`, atau nilai aman lain tanpa alasan domain eksplisit.

### I-007 — Policy != hardware state
`DesiredIntent` dan `ActualHardwareState` adalah dua fakta berbeda.

### I-008 — Stale snapshot cannot prove current hardware
Snapshot lama tidak boleh membuktikan state hardware setelah generation/operation baru.

## C. Safety

### I-009 — Sensor failure cannot silently enable charging
Failure pada sensor kritis harus menghasilkan explicit degraded/fault behaviour.

### I-010 — Thermal switch is authoritative
Jika thermal protection disabled, threshold thermal tidak boleh mengubah policy.

### I-011 — Safety has priority
Recovery, shutdown, hardware fault, dan sensor fault mengalahkan optimisasi charge-limit/ETA.

## D. Ownership recovery

### I-012 — Ownership deletion requires verified restoration
Ownership tidak boleh dihapus hanya karena write restore berhasil; actual state harus diverifikasi.

### I-013 — Corrupt ownership is not absence
Ownership file korup tidak boleh dianggap seolah tidak ada ownership.

### I-014 — Startup recovery precedes policy
Recovery ownership harus selesai sebelum normal policy boleh melakukan mutation.

## E. Concurrency

### I-015 — Serialized state mutation
State machine dan hardware intent hanya boleh dimutasi oleh satu serialized runtime owner.

### I-016 — No stale async completion
Verification/retry operation lama tidak boleh mengubah state setelah generation baru diterbitkan.

## F. Runtime

### I-017 — One shutdown sequence
SIGTERM, SIGINT, IPC shutdown, dan internal fatal shutdown menggunakan satu sequence.

### I-018 — Scheduler is not authority
Scheduler hanya menentukan kapan evaluasi dilakukan.

### I-019 — Netlink is not source of truth
Netlink hanya memicu re-read/reconciliation.

## G. Configuration

### I-020 — One validation authority
Semua konfigurasi runtime harus melewati validator yang sama.

### I-021 — Invalid config is preserved
Config invalid tidak boleh ditimpa otomatis dengan default.

### I-022 — Config change reconciles immediately
Perubahan policy config menghasilkan `ConfigChanged` dan evaluasi ulang segera.

## H. Testing

Setiap invariant kritis wajib memiliki test eksplisit:

```rust
unowned_hardware_never_modified()
partial_write_never_becomes_synced()
verification_failure_invalidates_sync()
stale_snapshot_cannot_prove_current_state()
corrupt_ownership_is_not_treated_as_missing()
shutdown_restores_owned_hardware()
config_change_triggers_reconciliation()
```

## Acceptance

Compile atau basic coverage saja tidak cukup. Perubahan dianggap benar hanya jika invariant tetap berlaku.
