# 06 — Ownership & Crash Recovery

## Tujuan
Ownership adalah kontrak yang memungkinkan daemon tahu state hardware mana yang boleh dipulihkan setelah crash.

## State
```text
NotOwned
 → Acquiring
 → Owned
 → Releasing
 → NotOwned
```
Recovery states:
```text
Recovery
RecoveryFailed
Corrupt
```

## Acquisition
```text
read actual baseline
 → validate baseline
 → persist Acquiring
 → apply target
 → readback
 → verify
 → persist Owned
```

Jangan menyimpan `Owned` sebelum hardware benar-benar verified.

## Release
```text
persist Releasing
 → restore original state
 → verify
 → clear state
```
Jika restore gagal, state tidak boleh dihapus.

## Crash cases
Harus ada deterministic rule untuk crash:
- sebelum `Acquiring`;
- setelah `Acquiring`;
- saat write;
- setelah write sebelum verify;
- setelah verify sebelum commit;
- saat release.

## Journal
Snapshot sederhana dapat ditingkatkan menjadi journal phase dengan:
```text
schema_version
operation_id
ownership_generation
phase
original_state
target_state
```

## Corrupt state
Corrupt ownership tidak boleh langsung dihapus dan tidak boleh memicu takeover. Masuk recovery/degraded mode sampai aman untuk menentukan tindakan.

## Startup
```text
load ownership
 → if present: recover first
 → verify restore
 → clear committed state
 → only then enable policy
```

## Acceptance criteria
1. Kill/crash di setiap transaction phase tested.
2. Restore failure mempertahankan evidence.
3. Corrupt journal tidak menjadi normal ownership.
4. Dua daemon tidak dapat mengambil ownership bersamaan.
