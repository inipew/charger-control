# 06 — OWNERSHIP, PERSISTENCE & CRASH RECOVERY

## Tujuan

Menjamin daemon tidak meninggalkan charging hardware dalam state yang tidak terkelola setelah crash, reboot, SIGKILL, kernel failure, atau persistence failure.

## Ownership state

```rust
enum OwnershipState {
    NotOwned,
    Acquiring,
    Owned,
    Releasing,
    Recovery,
    RecoveryFailed,
}
```

## Journal record

Minimal:

```text
format_version
operation_id
generation
phase
original_state
target_state
timestamp
```

## Acquire protocol

```text
read actual
→ validate actual
→ persist Acquiring atomically
→ mutate hardware
→ verify
→ persist Owned
```

Jika persistence Acquiring gagal, jangan melakukan controlled mutation.

## Release protocol

```text
persist Releasing
→ restore original
→ verify actual
→ clear ownership
```

Ownership tidak boleh dihapus sebelum verification.

## Crash points

Wajib mampu recovery jika crash terjadi:

```text
before persistence
between Acquiring and write
mid-write
after write before verify
after verify before Owned
after Releasing before restore
after restore before clear
```

## Startup recovery

```text
process lock
→ load ownership
→ validate journal
→ if stale: recovery
→ verify
→ clear only after success
→ start normal policy
```

Recovery harus berjalan sebelum policy normal.

## Corrupt ownership

Jika journal corrupt:

```text
DO NOT delete
DO NOT assume NotOwned
DO NOT automatically enable charging
enter explicit RecoveryFailed/Corrupt state
```

Operator harus bisa melihat alasan recovery tidak dapat dipastikan.

## Atomic persistence

Gunakan:

```text
write temp
→ flush
→ fsync
→ atomic rename
```

Directory durability perlu dipertimbangkan untuk filesystem yang mendukungnya.

## Repeated recovery

Recovery harus idempotent. Menjalankan daemon berkali-kali terhadap ownership stale yang sama tidak boleh menghasilkan state semakin buruk.

## Original state

Original state harus mewakili kondisi hardware sebelum daemon mengambil kontrol, bukan asumsi default.

Jika original state tidak dapat dibaca secara reliable, ownership acquisition gagal secara konservatif.

## Tests

Simulasikan setiap crash point menggunakan `MockPersistence` dan `MockHardwareIo`. Tidak perlu membunuh proses nyata untuk unit test.

Acceptance:

- journal atomic;
- recovery deterministic;
- corrupt state tidak hilang;
- restore verified;
- ownership hanya cleared setelah success;
- recovery idempotent;
- policy tidak berjalan sebelum recovery.
