# 18 — Android & Magisk Lifecycle Contract

## 1. Lifecycle matrix

```text
install → boot → start → running
restart → recovery → running
disable → shutdown → stopped
update → stop/recovery → running
rollback → recovery → running
uninstall → shutdown → stopped
crash → restart → recovery → running
```

Setiap transition harus mempunyai owner dan acceptance criteria.

## 2. Startup invariant

Policy mutation tidak boleh terjadi sebelum:

```text
singleton lock
 → config valid
 → profile/capability valid
 → ownership recovery
 → fresh snapshot
```

Ini mencegah daemon baru menginjak operation daemon lama yang belum direcover.

## 3. Magisk service

`service.sh` harus bootstrap daemon secara non-blocking. Jangan menjalankan charging loop kedua di shell.

```text
service.sh
 → environment setup
 → start daemon
 → return
```

## 4. Crash

Crash harus diperlakukan berbeda dari clean shutdown:

```text
crash
 → journal remains
 → supervisor/restart
 → startup recovery
 → actual read
 → reconcile
```

Jangan clear ownership pada crash handler sebelum hardware state diketahui.

## 5. Update race

```text
old daemon alive
new daemon starts
```

Harus dicegah oleh singleton lock. Update process sebaiknya memastikan old process stopped sebelum new process memperoleh writer role.

## 6. Disable/uninstall

```text
block new mutation
 → finalize/release ownership
 → verify required state
 → stop daemon
 → confirm process gone
 → disable/remove module
```

Jika finalization gagal, recovery evidence harus tetap ada.

## 7. Reboot

Jangan bergantung pada SIGTERM. Abrupt reboot harus recoverable melalui durable ownership journal.

## 8. Boot readiness

Node dapat muncul terlambat. Gunakan bounded readiness/probe retry, bukan infinite boot blocking.

## 9. Testing

```text
[ ] cold boot
[ ] reboot with charger attached
[ ] reboot unplugged
[ ] crash during write
[ ] crash during verify
[ ] restart
[ ] update
[ ] rollback
[ ] disable
[ ] uninstall
[ ] delayed sysfs availability
[ ] singleton race
```

## 10. Acceptance criteria

1. Tidak ada double writer.
2. Policy tidak mendahului recovery.
3. Boot script tidak blocking.
4. Crash/reboot dapat recover.
5. Disable/uninstall memastikan process stopped.
6. Failure finalization tidak menghapus evidence.
