# 18 — Android & Magisk Lifecycle Contract

## Lifecycle wajib
```text
install → boot → start → running
restart → recovery → running
disable → shutdown → stopped
update → restart/recovery
rollback → recovery
uninstall → shutdown → stopped
crash → supervisor restart → recovery
```

## Invariant
- policy tidak aktif sebelum ownership recovery selesai;
- hanya satu daemon instance boleh memegang controller;
- disable/uninstall harus menghentikan writer;
- boot script bukan second charging policy.

## Magisk
Gunakan late-start service untuk daemon non-blocking. Boot script harus singkat; jangan membuat boot tertahan karena polling atau hardware probing tak terbatas.

## Process identity
Gunakan process lock/pid semantics yang mencegah dua instance. Update harus menghentikan old process dan memastikan benar-benar stopped sebelum new process melakukan hardware mutation.

## Startup
```text
lock
 → config
 → validate profile/capability
 → load ownership
 → recovery
 → baseline snapshot
 → policy loop
```

## Disable/uninstall
```text
request shutdown
 → restore owned hardware
 → verify
 → stop daemon
 → verify process gone
 → disable/remove
```

Jika restore gagal, jangan berpura-pura uninstall sudah aman; pertahankan recovery evidence dan laporkan degraded state.

## Acceptance criteria
1. Boot/reboot tested.
2. Update tidak menghasilkan dua writer.
3. Crash recovery deterministic.
4. Disable/uninstall tidak meninggalkan process aktif.
5. Boot integration tidak block.
