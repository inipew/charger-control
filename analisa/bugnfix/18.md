# 18 — Android & Magisk Lifecycle Contract

## Lifecycle yang harus diuji
```text
install -> boot -> service start -> normal
restart -> disable -> enable
update -> rollback -> uninstall
crash -> automatic restart
```

## Invariant
- **I-LIFE-001**: startup harus recovery state sebelum policy baru melakukan mutation.
- **I-LIFE-002**: shutdown/restart harus satu graceful path.
- **I-LIFE-003**: module disabled/uninstalled tidak boleh meninggalkan writer aktif.
- **I-LIFE-004**: script boot tidak boleh menjadi second implementation of charging policy.

## Magisk
Boot integration sebaiknya mengikuti lifecycle Magisk yang sesuai. `service.sh` digunakan untuk late-start service dan pekerjaan non-blocking; blocking work tidak boleh menghambat boot.

Daemon harus memiliki pid/process ownership yang jelas sehingga update/restart tidak menghasilkan dua instance yang sama-sama menulis hardware.

## Startup recovery
```text
process start
 -> lock/single instance
 -> load config
 -> validate profile
 -> recover ownership journal
 -> read actual hardware
 -> establish baseline
 -> enable policy loop
```

## Disable/uninstall
Urutan aman:
1. request graceful shutdown;
2. restore ownership bila valid;
3. stop process;
4. verify process benar-benar berhenti;
5. baru remove module/config bila relevan.

## Acceptance criteria
1. Dua daemon instance tidak dapat aktif bersamaan.
2. Crash setelah acquire dan sebelum apply dapat dipulihkan.
3. Restart tidak menyebabkan transient write race.
4. Disable/uninstall tidak meninggalkan stale process yang mengontrol charging.
