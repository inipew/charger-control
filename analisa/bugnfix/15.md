# 15 — Desired, Applied, Actual & Verified State

## Masalah
Empat konsep sering keliru disatukan. `set succeeded` hanya berarti write call berhasil; bukan bukti hardware berada pada state yang diinginkan.

## Model
```text
DesiredState
     ↓
ApplyResult
     ↓
AppliedState
     ↓ readback
ActualState
     ↓ evidence rules
VerifiedState
```

## Data controller
Simpan:
```text
desired intent
action generation
operation ID
last apply result
actual readback
verification result
snapshot age
retry metadata
```

## Reconciliation
```text
fresh snapshot
 → policy decision
 → desired
 → compare actual
 → apply only if mismatch
 → readback
 → verify
 → commit
```

Jika actual berubah karena external actor, jangan menganggap previous verification masih valid.

## External mutation
```text
desired=Disabled
verified=Disabled
external actor → Enabled
        ↓
actual=Enabled
        ↓
reconcile
```
Repeated mutation harus memicu bounded retry/backoff atau degraded ownership.

## No false success
API controller tidak boleh mengembalikan `Synced` hanya karena semua `write()` mengembalikan success bila profile mengharuskan readback.

## Acceptance criteria
1. Status API menampilkan empat layer state.
2. External mutation test pass.
3. Verified state memiliki evidence timestamp/operation.
4. No redundant write ketika actual sudah verified.
