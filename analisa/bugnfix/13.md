# 13 — Power Supply & Kernel Semantics

## Tujuan
Menetapkan kontrak semantik antara daemon dan Linux power-supply sysfs/uevent. Daemon tidak boleh menganggap keberadaan satu node, nilai current, atau `STATUS` sebagai fakta universal semua device.

## Invariant
- **I-PS-001**: setiap property memiliki unit dan makna yang dinormalisasi sebelum masuk policy.
- **I-PS-002**: property yang tidak tersedia adalah `Unsupported/Unknown`, bukan otomatis `false`, `0`, `Offline`, atau `Fault`.
- **I-PS-003**: `ONLINE`, `PRESENT`, `STATUS`, current, dan capacity adalah sinyal berbeda dan tidak boleh dipertukarkan.
- **I-PS-004**: konversi nilai kernel harus checked dan tidak boleh overflow/wrap.
- **I-PS-005**: tanda current (`+/-`) harus didefinisikan per profile; jangan menebak secara global.

## Model data yang disarankan
Pisahkan:

```text
RawSysfsValue
  -> ParsedValue
  -> NormalizedSensor
  -> SensorSnapshot
  -> PolicyInput
```

Contoh normalized sensor:

```text
BatteryPresence = Present | Absent | Unknown
PowerOnline     = Online | Offline | Unknown
ChargeStatus    = Charging | Discharging | NotCharging | Full | Unknown
Current         = Known(i64 microamp) | Unknown
Temperature     = Known(i32 deciC) | Unknown
Capacity        = Known(u8 percent) | Unknown
```

## Validasi
- capacity hanya valid 0..100.
- temperature memiliki batas sanity yang profile-specific.
- current boleh negatif jika kernel/profile mendefinisikannya demikian.
- nilai mustahil tidak boleh langsung menjadi `Fault`; bedakan `Invalid`, `Stale`, `Unsupported`, dan `Fault`.
- timestamp snapshot harus monotonic.

## `*_NOW` vs average
Policy charging protection menggunakan instantaneous value bila memang diperlukan untuk safety, sedangkan telemetry/estimation boleh memakai average. Jangan mencampur keduanya.

## Uevent
Netlink adalah accelerator. Uevent dapat hilang, terlambat, atau datang berulang. Correctness tetap berasal dari reconciliation/polling.

## Acceptance criteria
1. Semua reader menggunakan satu normalisasi semantik.
2. Tidak ada `0`/`false` default untuk property yang tidak ada tanpa alasan eksplisit.
3. Tidak ada integer narrowing tanpa checked conversion.
4. Test mencakup missing node, malformed value, negative current, stale snapshot, duplicate event, dan property vendor tambahan.
5. Profile dapat menyatakan sign convention current dan node yang menjadi evidence utama.
