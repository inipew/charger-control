# 13 — Power Supply & Kernel Semantics

## Tujuan
Mencegah policy membuat asumsi Linux/Android power-supply yang tidak universal.

## Prinsip
Linux power-supply properties bersifat capability-driven: tidak semua hardware menyediakan property yang sama. Reader harus membedakan absent, unreadable, invalid, dan valid value.

## Semantic model
```text
raw sysfs
 ↓ parse
property semantic
 ↓ normalize unit/sign
SensorSnapshot
 ↓
DecisionEngine
```

## Presence
Jangan menyamakan:
```text
ONLINE=0
STATUS=NotCharging
CURRENT=0
```
ketiganya memiliki semantic berbeda.

Target:
```text
Online
Offline
Unknown
```
berdasarkan evidence yang didefinisikan profile.

## Status vs electrical current
`STATUS=Charging` adalah kernel-reported status; current adalah electrical measurement. Current dapat dipengaruhi load, sign convention, measurement delay, dan driver implementation. Keduanya tidak boleh dicampur sebagai satu field tanpa provenance.

## Units
Property power-supply harus dikonversi sesuai unit documented property. Internal domain memakai unit explicit:
```text
temperature → deci-Celsius
current → mA
capacity → percent
```
Conversion dilakukan sekali dan checked.

## Absent property
```text
property absent + optional → capability unavailable
property absent + required → profile unsupported/degraded
read error → sensor error
malformed → invalid sensor
```

## Staleness
Snapshot harus memiliki capture age. Cached value tidak boleh diperlakukan sebagai fresh hanya karena FD masih terbuka.

## Acceptance criteria
1. Semua property memiliki unit mapping.
2. Absent/invalid/read-error dibedakan.
3. Current sign dinormalisasi di reader/profile.
4. Presence tidak disimpulkan dari satu heuristic universal.
5. Real-device fixture menyimpan contoh raw values per profile.
