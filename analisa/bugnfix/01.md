# 01 — MASTER REMEDIATION SPECIFICATION

**Status:** authoritative remediation plan.
**Scope:** seluruh daemon, core, CLI, persistence, IPC, hardware control, policy, scheduler, dan Android runtime.

## Tujuan

Mengubah ChargerControl menjadi daemon Android yang deterministic, fail-safe, crash-recoverable, testable, dan memiliki boundary arsitektur yang jelas.

## Invariant utama

1. Hanya `HardwareController` yang boleh mengubah charging-control sysfs.
2. `Policy` menentukan **WHAT**, `Scheduler` menentukan **WHEN**, `HardwareController` menentukan **HOW**, `HardwareIo` melakukan I/O.
3. `Unknown != Offline != Fault != Disabled`.
4. Ownership harus dipersist sebelum hardware dikendalikan.
5. Crash tidak boleh meninggalkan ownership tanpa recovery path.
6. Verification wajib setelah hardware mutation.
7. Verification gagal tidak boleh dipublikasikan sebagai `Synced`.
8. Sensor kritis gagal tidak boleh berubah menjadi nilai aman palsu seperti `0`.
9. IPC tidak boleh melakukan hardware mutation langsung.
10. IPC shutdown, SIGTERM, dan SIGINT harus menuju satu graceful shutdown path.
11. Netlink, EMA, ETA, dan scheduler hanyalah optimisasi; kehilangan semuanya tidak boleh melemahkan safety.

## P0 — Safety blockers

### Shutdown

IPC hanya menghasilkan `ShutdownRequested`. Main runtime melakukan:

```text
request
→ stop new mutations
→ stop retry
→ restore owned hardware
→ verify restoration
→ persist unresolved ownership if failed
→ close resources
→ exit
```

Tidak boleh ada `process::exit()` dari worker IPC.

### Thermal

`thermal_cutoff=false` berarti thermal policy sepenuhnya nonaktif. Jika aktif:

```text
T >= cutoff       → ThermalCutoff
T <= cutoff - hysteresis → resume
```

Hysteresis harus configurable dan tervalidasi.

### Bypass

Bypass/manual control harus masuk melalui `HardwareIntent`, bukan menulis sysfs langsung dari IPC/CLI.

### IPC

Gunakan permission minimal `0660` atau lebih ketat, owner/group yang sesuai, dan capability authorization untuk operasi mutating.

### Config

Bedakan:

```text
missing → defaults/create
valid   → use
parse error → reject/preserve
I/O error → reject
```

Jangan pernah menimpa config korup dengan defaults.

    NotOwned,

    NormalCharging,

State policy, hardware, dan ownership tidak boleh digabung menjadi satu enum.

## Hardware transaction

Acquisition:

```text
read actual
→ validate
→ persist Acquiring
→ write target
→ read actual
→ verify
→ persist Owned
```

Release:

```text
persist Releasing
→ restore original
→ verify
→ clear ownership
```

Partial write wajib direkonsiliasi dengan membaca seluruh control nodes kembali.

## Ownership journal

Minimal simpan:

```text
version
operation_id
generation
phase
original_state
target_state
timestamp
```

Ownership hanya boleh dihapus setelah restoration berhasil diverifikasi.

## Battery reader

Gunakan satu abstraction `BatteryReader`. Semua path berasal dari `HardwareProfile`.

```rust
struct SensorSnapshot {
    capacity_pct: Option<u8>,
    temp_dc: Option<i32>,
    current_ma: Option<i32>,
    online: Option<bool>,
    charging: Option<bool>,
    ts: Instant,
}
```

Tidak boleh `unwrap_or(0)` untuk sensor safety-critical.

## Presence

Prioritas:

```text
authoritative online node
→ configured fallback
→ Unknown
```

Node yang ada tetapi gagal dibaca menghasilkan `Unknown`, bukan `Offline`.

## Policy

Priority default:

```text
Shutdown
> Recovery
> Disabled
> Hardware fault
> Sensor fault
> Offline
> Thermal protection
> Manual bypass
> Charge limit
> Normal charging
```

Charge limit menggunakan hysteresis:

```text
Charging + capacity >= limit → LimitReached
LimitReached + capacity <= resume → Charging
```

## Scheduler dan Netlink

Scheduler hanya menentukan kapan evaluasi. Netlink hanya mempercepat evaluasi.

Deadline controller harus mencakup verification dan retry. `poll()` harus membedakan event, timeout, error, dan `EINTR`, serta memproses `POLLERR/POLLHUP/POLLNVAL`.

## Startup

```text
process lock
→ config load/validate
→ logger
→ persistence/profile/I/O
→ stale ownership recovery
→ capability probe
→ reader/policy/scheduler
→ IPC/netlink
→ event loop
```

Normal policy tidak boleh berjalan sebelum recovery ownership selesai atau masuk explicit recovery-failed state.

## Testing

Wajib mencakup policy boundaries, partial writes, verification, ownership crash points, corrupt persistence, IPC malformed input, shutdown, retry/backoff, stale snapshot, dan config reload.

## Definition of Done

Remediation dianggap selesai hanya jika:

- tidak ada direct sysfs mutation di luar controller;
- semua critical state memiliki semantic representation;
- ownership atomic dan recoverable;
- verification generation-aware;
- config validation terpusat;
- shutdown terpusat;
- IPC terautorisasi;
- scheduler tidak memegang policy authority;
- Netlink failure aman;
- fault injection deterministic tersedia;
- invariant tests lulus;
- integration shutdown/recovery lulus;
- release build dan static analysis lulus.
