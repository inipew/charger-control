# 01 — Master Remediation Specification

## Status audit
Repository `inipew/charger-control` pada `master` sudah memiliki fondasi yang baik: workspace terpisah, hardware abstraction, ownership persistence, verification, netlink, scheduler, fake clock, dan mock hardware. Namun belum layak diberi label production-grade karena masih ada safety/consistency gap pada shutdown, thermal policy, bypass, IPC, configuration, hardware transaction, dan recovery.

## Temuan kritis

### 🔴 P0 — Shutdown IPC dapat melewati restore
IPC tidak boleh memanggil `process::exit()` dari worker. Shutdown harus menjadi event yang diproses monitor/runtime, lalu hardware ownership dipulihkan dan diverifikasi sebelum proses keluar.

```text
IPC/SIGTERM
 → ShutdownRequested
 → stop new policy work
 → restore ownership
 → verify
 → persist final state
 → close IPC
 → exit
```

### 🔴 P0 — `thermal_cutoff` harus benar-benar menjadi master switch
`thermal_cutoff=false` wajib membuat thermal policy inactive. Prediction/scheduler thermal juga harus inactive. Jangan membiarkan `max_temp_dc` sendiri mengaktifkan cutoff.

### 🔴 P0 — Bypass tidak boleh direct sysfs
Semua hardware mutation harus melewati `HardwareController`. Bypass adalah intent/mode, bukan API yang menulis node sendiri.

### 🔴 P0 — IPC tidak boleh world-writable
Socket `0666` terlalu permisif untuk root daemon. Gunakan permission/group restrictive dan authorization command.

### 🟠 P1 — Config corrupt tidak boleh fallback lalu overwrite
Missing config boleh membuat default jika memang policy mengizinkan. Parse/I/O/validation error harus ditolak tanpa menimpa file asli.

### 🟠 P1 — Validation harus berada di domain config
CLI dan daemon harus menggunakan `Config::validate()` dan `normalize()` yang sama.

### 🟠 P1 — Hardware partial failure harus direkonsiliasi
Partial write harus dibaca ulang dan dikonvergensikan ke target aman; retry tidak boleh menjadi satu-satunya recovery.

### 🟠 P1 — Ownership harus transactional
Snapshot ownership perlu ditingkatkan menjadi journal/phase state yang recoverable pada crash.

## Target architecture

```text
CLI / IPC / Signal / Netlink
          ↓ events
      Runtime/EventLoop
          ↓
     DecisionEngine
          ↓ HardwareIntent
    HardwareController
          ↓
       HardwareIo
          ↓
        sysfs
```

Ownership/persistence dan verification mengelilingi transaction, bukan menjadi side-effect tersebar.

## Absolute invariants
1. Hanya `HardwareController` yang boleh memutasi hardware.
2. Desired != applied != actual != verified.
3. `Unknown != Offline != Fault`.
4. Scheduler menentukan WHEN; policy menentukan WHAT; controller menentukan HOW.
5. Netlink mempercepat reaction; polling/reconciliation menjaga correctness.
6. Crash tidak boleh menghilangkan ownership evidence.
7. Config invalid tidak boleh berubah menjadi default secara diam-diam.
8. Safety failure lebih penting daripada availability.
