# 10 — Testing, Fault Injection & Release Gate

## Tujuan
Charging daemon tidak cukup diuji dengan happy path. Safety harus dibuktikan pada failure path.

## Test layers
```text
pure unit
 → component/mock hardware
 → integration runtime
 → crash/fault injection
 → real-device compatibility
```

## Policy tests
Wajib mencakup:
```text
disabled/offline/unknown
limit boundary/resume boundary
thermal enabled/disabled
fault/recovery
manual mode priority
```

## Hardware tests
```text
all success
partial write
all failure
missing optional/required
mixed/unknown state
verification fail
external mutation
retry/backoff
```

## Ownership tests
Inject crash pada setiap phase:
```text
before acquire
acquiring
writing
written-before-verify
verified-before-commit
releasing
restore failure
```
Restart harus selalu menghasilkan recovery decision yang deterministic.

## IPC tests
```text
unauthorized
malformed
oversized
slow client
concurrent clients
shutdown
bypass
```

## Fuzz/property tests
Fuzz parser config, IPC, sensor values, ownership record. Property-test charge-limit hysteresis, temperature hysteresis, and state transition invariants.

## Release gate
Reject release bila salah satu critical invariant gagal. Minimal:
```text
no direct writes
safe shutdown
secure IPC
config integrity
ownership recovery
partial-write recovery
fault-safe policy
```

## Real device
Mock success tidak membuktikan vendor semantics. Setiap supported profile perlu real-device evidence untuk node values, sign convention, suspend/resume, external actor, dan reboot.
