# 10 — Testing, Fault Injection & Release Gate

## 1. Prinsip

Untuk daemon yang mengontrol charging, test happy-path hanya membuktikan bahwa sistem bekerja ketika semua actor kooperatif. Production readiness terutama ditentukan oleh behaviour ketika sensor hilang, node vendor berbeda, process crash, IPC diserang, atau hardware tidak mengikuti write.

## 2. Test pyramid

```text
Pure unit
   ↓
Component tests + MockHardware
   ↓
Runtime integration
   ↓
Fault/crash injection
   ↓
Real Android device
   ↓
Soak / reboot / suspend-resume
```

Semakin dekat ke hardware, semakin mahal test sehingga deterministic lower-level tests harus menutup mayoritas state machine.

## 3. Policy matrix

Generate matrix untuk:

```text
enabled × online × sensor validity × capacity × temperature × previous state
```

Minimal boundary:

```text
capacity = limit-1 / limit / limit+1
capacity = resume-1 / resume / resume+1
temp = threshold-1 / threshold / threshold+1
temp = threshold-hysteresis-1 / exact / +1
```

Test thermal dengan `thermal_cutoff=false` dan `true` secara terpisah.

## 4. Fault recovery

Test:

```text
invalid snapshot #1 → Fault
invalid #2 → Fault/recovery=0
valid #1 → recovery=1
valid #2 → recovery=2
valid #N → normal reevaluation
valid, invalid, valid → streak reset
```

Pastikan counter tidak pernah bisa overflow atau recover karena satu sample valid yang tidak consecutive.

## 5. Hardware mock

Mock harus merepresentasikan bukan hanya success/failure boolean tetapi sequence:

```text
write(node A) = success
write(node B) = EIO
read(A) = OFF
read(B) = ON
```

Dengan ini partial failure dapat diuji sebagai state nyata.

## 6. Verification tests

```text
write success + immediate stale read
write success + delayed correct read
write success + permanently wrong read
read unknown
mixed nodes
external actor changes state after verification
```

Assertion harus mencakup state transition, retry scheduling, persisted ownership, dan logs/correlation ID.

## 7. Crash injection

Inject termination pada setiap checkpoint:

```text
before ownership persist
after ownership persist
before first write
after first write
mid-write sequence
after final write
before readback
after readback
before verify commit
after verified commit
before release persist
```

Restart harus menghasilkan recovery yang deterministic.

## 8. Persistence corruption

Fixture:

```text
empty
truncated
invalid syntax
wrong schema
wrong checksum
unexpected enum
oversized record
symlink replacement
```

Daemon tidak boleh menganggap corruption sebagai clean state.

## 9. IPC security tests

```text
wrong uid/group
unauthorized command
malformed frame
oversized frame
slowloris client
many concurrent clients
client disconnect
shutdown racing mutation
```

Pastikan worker tidak dapat memicu direct hardware write.

## 10. Property/fuzz tests

Fuzz:

```text
TOML config
sensor raw strings
status strings
IPC frames
ownership records
profile definitions
```

Property:

```text
valid config never creates impossible effective thresholds
same policy input → same output
Unmanaged → zero hardware writes
verification failure ≠ verified success
```

## 11. Fake clock

Semua timeout/deadline/retry/debounce harus dapat diuji dengan fake monotonic clock. Test tidak boleh `sleep(60s)` untuk membuktikan backoff 60 detik.

## 12. Real-device matrix

Mock tidak membuktikan vendor semantics. Untuk setiap supported profile record:

```text
device / SoC / kernel / Android version
control nodes
read nodes
units/sign
status mapping
online semantics
boot timing
suspend/resume
reboot
external actor behaviour
```

## 13. Soak test

Run minimal beberapa jam dengan:

```text
plug/unplug cycles
charge-limit transitions
thermal changes
screen on/off
Doze/suspend
netlink restart
service restart
```

Observe CPU, wakeups, logs, write frequency, and state convergence.

## 14. Release gate

Release **MUST fail** jika salah satu berikut gagal:

```text
[ ] direct hardware write audit
[ ] graceful shutdown
[ ] IPC authorization
[ ] config corruption handling
[ ] ownership crash recovery
[ ] partial-write reconciliation
[ ] Fault fail-safe
[ ] Unmanaged no-write
[ ] netlink fallback
[ ] real-device compatibility
```

## 15. Evidence package

Setiap release menyimpan:

```text
commit SHA
build target/toolchain
unit/integration test result
fault-injection result
supported device matrix
artifact checksum
config/schema version
```

Production claim harus dapat diaudit kembali dari evidence tersebut.
