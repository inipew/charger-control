# 10 — TESTING, FAULT INJECTION & RELEASE GATE

## Prinsip

Testing harus membuktikan invariant dan failure behaviour, bukan hanya line coverage.

## Dependency injection

Core sebaiknya memiliki:

```rust
trait HardwareIo { ... }
trait PersistenceIo { ... }
trait Clock { ... }
```

Production menggunakan sysfs/filesystem/clock nyata. Test menggunakan mock/in-memory/fake clock.

## Fake clock

Retry, verification deadline, debounce, scheduler interval, dan backoff tidak boleh membutuhkan real `sleep()` dalam unit test.

```text
FakeClock
→ advance(30s)
→ retry fires
```

## FaultPlan

Fault injection deterministic:

```rust
enum Fault {
    ReadFailed,
    WriteFailed,
    NodeMissing,
    PermissionDenied,
    VerificationFailed,
    PersistenceFailed,
}
```

Dukung sequence:

```text
write #1 → OK
write #2 → EIO
write #3 → OK
```

## Policy test matrix

Wajib:

- disabled;
- online/offline/unknown;
- charging/not charging;
- limit exact boundary;
- resume exact boundary;
- thermal cutoff;
- thermal hysteresis;
- thermal disabled;
- sensor invalid;
- fault recovery;
- config change;
- stale snapshot.

## Hardware test matrix

Wajib:

- all required writes succeed;
- optional node missing;
- required node missing;
- partial write;
- total failure;
- mixed state;
- external modification;
- verification retry;
- retry exhaustion;
- generation invalidation;
- restoration.

## Ownership test matrix

Simulasikan crash/failure pada:

```text
before Acquiring
after Acquiring
mid-write
after write before verify
after verify before Owned
Releasing
restore failure
clear failure
corrupt journal
```

## IPC test matrix

- unauthorized command;
- malformed packet;
- oversized packet;
- unsupported protocol version;
- timeout;
- client disconnect;
- concurrent requests;
- shutdown during operation;
- bypass authorization.

## Runtime integration

Test wajib:

```text
daemon starts
→ acquires ownership
→ applies target
→ verifies
→ shutdown request
→ restores original
→ verifies restore
→ clears ownership
→ exits
```

Juga:

```text
apply
→ kill process
→ restart
→ detect stale ownership
→ recover
→ verify
```

## Static/release gate

Minimal:

```text
cargo fmt --check
cargo check --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo test --release --workspace
```

Tambahkan target Android cross-build yang sesuai toolchain project.

## Release gate

Tidak boleh release jika:

- panic path safety-critical masih ada;
- direct sysfs writer ditemukan di luar boundary;
- corrupt ownership dapat dihapus otomatis;
- shutdown tidak restore;
- verification failure dapat dipublikasikan sebagai success;
- critical sensor failure diam-diam menjadi zero/default;
- integration recovery gagal.
