# 26 — Android Compatibility Matrix

## 1. Production support definition

Compile success bukan compatibility. A device hanya dapat disebut tested jika charging topology, node semantics, lifecycle, recovery, dan safety paths telah diuji pada hardware nyata.

## 2. Matrix dimensions

| Dimension | Required evidence |
|---|---|
| Android | API/version |
| Device | model/codename |
| SoC | family/model |
| Kernel | version/config |
| Charger driver | implementation |
| Battery topology | supplies/properties |
| Control nodes | paths/values |
| Vendor actors | known writers |
| SELinux | access/denials |
| Magisk | version |
| Profile | version/capability |

## 3. Support tiers

```text
Tested
 → real device + relevant suite passed

Compatible by capability
 → profile/capability match, limited real evidence

Unsupported
 → required capability absent or semantics unknown
```

Jangan menyatakan seluruh SoC family supported hanya karena satu device berhasil.

## 4. Profile validation

Device identity hanya kandidat. Final acceptance berdasarkan capability:

```text
identity
 → candidate profile
 → node probe
 → semantics validation
 → capability result
```

Mismatch harus mencegah speculative writes.

## 5. Regression evidence

Untuk setiap tested device simpan:

```text
raw nodes
normalized values
control operations
verification traces
boot/reboot
plug/unplug
suspend/resume
external actor
crash recovery
```

## 6. Matrix gates

Profile update yang mengubah node semantics harus menjalankan regression fixture seluruh device yang menggunakan profile tersebut.

## 7. Testing

```text
[ ] fresh install
[ ] upgrade
[ ] reboot
[ ] charger attached boot
[ ] unplug/replug
[ ] limit transition
[ ] thermal transition
[ ] daemon crash
[ ] suspend/resume
[ ] disable/uninstall
[ ] external writer
```

## 8. Acceptance criteria

1. Support tier jelas.
2. Setiap tested device punya evidence.
3. Capability mismatch tidak write.
4. Profile regression teruji.
5. Release notes mencantumkan compatibility changes.
