# 05 — BATTERY SENSOR & READER SPECIFICATION

## Tujuan

Menjamin sensor battery memiliki semantics yang eksplisit, tidak menghasilkan fallback palsu, dan tahan terhadap perubahan vendor/kernel.

## Canonical snapshot

```rust
struct SensorSnapshot {
    capacity_pct: Option<u8>,
    temp_dc: Option<i32>,
    current_ma: Option<i32>,
    online: Option<bool>,
    charging: Option<bool>,
    ts: Instant,
}
```

Capacity tidak perlu `f32`; sumbernya integer persen.

## Sensor semantics

### Capacity

Valid range:

```text
0..=100
```

Nilai di luar range adalah invalid sensor data, bukan nilai policy.

### Temperature

Temperature menggunakan deci-Celsius (`dc`). Sanity range harus terpisah dari thermal policy.

```text
sanity validation != thermal cutoff
```

Sensor 80°C mungkin valid secara fisik tetapi harus memicu thermal policy; nilai absurd seperti 9999 harus dianggap invalid.

### Current

Unit internal harus `mA`. Conversion dari `i64` harus checked.

Pisahkan:

```text
battery current
input current
```

Sign convention ditentukan oleh profile karena vendor Android tidak seragam.

## Charging state

Jangan infer charging hanya dari `StopReason`.

Gabungkan:

```text
status
online
current
control state
```

menjadi semantic `ElectricalState`:

```rust
enum ElectricalState { Charging, Discharging, Idle, Unknown }
```

## Presence

Gunakan authoritative online nodes bila tersedia. Fallback hanya jika profile menyatakan valid.

```text
authoritative node read OK → Online/Offline
authoritative node read fail → Unknown
no authoritative node + valid fallback → fallback
insufficient evidence → Unknown
```

## Cached sysfs FDs

Semua cached sensor FD harus memiliki strategi rescan.

```text
normal read
→ failure/stale
→ mark invalid
→ rescan periodically
→ netlink event may accelerate rescan
```

Jangan membuka capacity/temp/status sekali lalu menganggap FD selalu valid.

## Node discovery

Hindari heuristik seperti “semua power_supply yang memiliki `online` adalah charger”. Gunakan configured/profile-driven nodes dengan priority.

```rust
struct OnlineNodeConfig {
    path: PathBuf,
    priority: u8,
}
```

Semantics:

```text
trusted online node = true → Online
all trusted nodes = false → Offline
no valid observation → Unknown
```

## No silent defaults

Dilarang:

```rust
read_capacity().unwrap_or(0)
read_temperature().unwrap_or(0)
read_current().unwrap_or(0)
```

Gunakan `Option`/semantic error dan biarkan policy menentukan degraded state.

## Sensor freshness

Snapshot harus memiliki timestamp monotonic. Sensor lama tidak boleh dipakai sebagai bukti kondisi sekarang setelah melewati freshness budget.

## Testing

Wajib menguji:

- capacity 0, 100, >100;
- temperature normal, cutoff, absurd;
- current positive/negative/zero;
- node missing;
- read EIO/ENODEV;
- cached FD stale;
- online node priority;
- charging status conflict;
- stale snapshot;
- config change.
