# 05 — Battery Sensor & Reader

## Prinsip
Reader menerjemahkan kernel/vendor raw values menjadi domain snapshot. Reader bukan tempat policy.

## Single reader abstraction
Target:
```text
BatteryReader trait
    ↓
CachedSysfsReader
    ↓
SensorSnapshot
```

Hilangkan duplicate generic APIs yang membaca hard-coded `/sys/class/power_supply/battery/*` bila profile-driven reader sudah tersedia.

## Profile-driven paths
Profile menentukan:
```text
capacity
status
temperature
battery current
input current
online/presence
```
Tidak boleh ada hidden fallback path yang mengubah semantic tanpa deklarasi profile.

## Units
Kernel power-supply values memiliki unit property-specific. Reader wajib mengonversi tepat sekali ke unit domain. Internal API harus explicit, misalnya `temp_dc` dan `current_ma`.

## Checked conversion
Jangan:
```rust
(value / 1000) as i32
```
Gunakan checked arithmetic dan range validation sebelum narrowing.

## Current semantics
Pisahkan:
```text
BatteryCurrent
InputCurrent
```
dan vendor sign convention harus dinormalisasi di reader/profile, bukan di policy.

## Presence
Urutan evidence:
```text
authoritative online node
 → profile-declared fallback
 → Unknown
```
Read failure pada authoritative node tidak boleh diam-diam berubah menjadi Offline.

## Cached FD
Cache adalah optimization. Read error harus meng-invalidate FD dan menjadwalkan rescan. Test driver topology changes/reconnect.

## Snapshot quality
Snapshot menyimpan age/timestamp monotonic. Nilai out-of-range, impossible transition, atau stale evidence harus ditandai invalid/unknown, bukan dipaksa menjadi valid.

## Acceptance tests
- absent property;
- malformed integer;
- overflow;
- negative current;
- vendor sign convention;
- stale FD;
- online read failure;
- no online capability;
- snapshot age.
