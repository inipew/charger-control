# 05 — Battery Sensor & Reader

## 1. Tujuan

Reader adalah boundary antara vendor/kernel `power_supply` dan domain policy. Tugas reader bukan menentukan apakah charging aman, melainkan membaca evidence, memvalidasi format, menormalisasi unit/sign, dan menghasilkan `SensorSnapshot` yang jujur.

## 2. Snapshot saat ini

Canonical snapshot:

```rust
struct SensorSnapshot {
    capacity_pct: Option<u8>,
    temp_dc: Option<i32>,
    current_ma: Option<i32>,
    status: Option<BatteryStatus>,
    online: Option<bool>,
    ts: Instant,
}
```

`Option` harus memiliki semantic nyata. `None` berarti evidence tidak tersedia/valid, bukan nilai aman.

## 3. Source semantics

Android `power_supply` properties dapat berbeda antar device. Reader harus menganggap node/property sebagai capability yang mungkin:

```text
absent
unreadable
invalid
stale
valid
```

Jangan membuat asumsi bahwa semua battery device menyediakan property yang sama.

## 4. Unit dan sign

Reader harus mengubah raw kernel unit ke domain unit secara eksplisit.

Contoh:

```text
µA → mA
0.1°C / tenths-degree → domain deci-degree sesuai kontrak
percentage → 0..100
```

Current sign harus didokumentasikan. Sebagian driver memakai positive untuk charging, sebagian dapat memberi semantics berbeda.

Jangan melakukan:

```rust
(value_i64 / 1000) as i32
```

tanpa range check. Gunakan checked conversion agar nilai out-of-range tidak wrap.

## 5. `online` bukan `status`

Bedakan:

```text
online = physical charger/power source presence evidence
status = battery charging state
```

Contoh valid:

```text
online=true
status=NotCharging
```

bisa berarti limit/control sedang aktif. Jangan mengartikan NotCharging sebagai offline.

## 6. Unknown vs invalid

Recommended mapping:

```text
property absent but optional → None
read error                  → None + diagnostic
parse invalid               → None + diagnostic
unknown enum                → typed Unknown/error
online=false                → Offline evidence
```

Jika property required untuk safety hilang, policy yang menentukan apakah masuk Fault. Reader tidak boleh mengarang fallback.

## 7. Cache

Jika menggunakan cached reader, setiap cached value harus mempunyai timestamp/age. Snapshot yang terlalu lama tidak boleh dianggap fresh.

```text
read at t0
cache
sleep/suspend
read at t1
if age > max_age → stale
```

Cache mengurangi sysfs I/O tetapi tidak boleh mengorbankan safety.

## 8. Duplicate reader implementations

Jika terdapat generic hard-coded battery paths dan profile-driven `CachedReader`, pilih satu abstraction utama:

```rust
trait BatteryReader {
    fn snapshot(&mut self, now: Instant) -> SensorSnapshot;
}
```

Profile menentukan source/capability; domain tetap menerima snapshot yang sama.

## 9. Status mapping

Vendor string harus dipetakan secara eksplisit:

```text
Charging → Charging
Full → Full
Not charging → NotCharging
Discharging → Discharging
Unknown → Unknown/error evidence
```

Jangan menganggap string baru vendor sebagai `Charging` atau `NotCharging` secara default.

## 10. Freshness

Setiap evaluation harus mengetahui apakah snapshot cukup baru. Netlink event tidak berarti snapshot otomatis berubah; setelah event, reader tetap harus membaca evidence baru.

## 11. Failure behaviour

Jika capacity valid tetapi temperature invalid:

```text
snapshot.temp=None
```

bukan:

```text
temp=0
```

Jika current overflow:

```text
current=None + error evidence
```

bukan truncated/wrapped value.

## 12. Testing

Reader test wajib mencakup:

```text
[ ] normal values
[ ] boundary 0/100%
[ ] negative/large raw current
[ ] µA conversion
[ ] malformed text
[ ] missing node
[ ] permission/read error
[ ] unknown status string
[ ] online false
[ ] online missing
[ ] stale cache
[ ] fresh cache
[ ] suspend/resume refresh
```

Tambahkan fixture untuk beberapa vendor layout agar parser tidak hanya cocok dengan satu perangkat.

## 13. Acceptance criteria

1. Reader tidak melakukan policy decision.
2. Tidak ada silent fallback untuk sensor invalid.
3. Unit/sign conversion teruji.
4. Overflow tidak dapat wrap ke nilai valid.
5. `online`, `status`, `current`, `capacity`, `temperature` tetap terpisah.
6. Snapshot memiliki freshness semantics.
7. Hanya satu canonical reader abstraction yang digunakan runtime.
