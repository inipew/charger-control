# 27 — Performance & Power Budget

## Prinsip
Daemon charging tidak boleh menghemat battery melalui algoritme charging tetapi menghabiskan battery lewat polling, wakeup, logging, atau CPU.

## Invariant
- **I-PERF-001**: scheduler memiliki bounded wakeup rate.
- **I-PERF-002**: sysfs reads dikelompokkan dan tidak dilakukan bila tidak diperlukan.
- **I-PERF-003**: event storm dicoalesce.
- **I-PERF-004**: logging repeated failures di-rate-limit.

## Budget yang perlu diukur
- CPU average dan peak;
- RSS memory;
- wakeups/menit saat idle;
- sysfs reads/menit;
- netlink event rate;
- writes/menit;
- log bytes/menit;
- startup latency.

## Scheduler
Polling interval harus adaptif tetapi memiliki upper/lower bound. Netlink event dapat mempercepat reconciliation. Saat unplugged/idle, heartbeat dapat diperpanjang karena policy tidak membutuhkan polling agresif.

EMA hanya boleh memengaruhi scheduling/estimation, bukan safety cutoff yang membutuhkan raw sensor evidence.

## Resource safety
Channel/event queue harus bounded. Producer yang terlalu cepat tidak boleh menyebabkan memory growth tanpa batas.

## Acceptance criteria
1. Idle daemon memiliki measured wakeup/CPU budget.
2. Event storm tidak menghasilkan write storm.
3. Memory tidak tumbuh pada synthetic long-run test.
4. Safety policy tetap benar ketika scheduler interval berubah.
5. Performance regression masuk CI atau release checklist.
