# 27 — Performance & Power Budget

## 1. Tujuan

Daemon yang menghemat charging tetapi membakar energi melalui wakeup, polling, logging, dan CPU adalah desain yang kontradiktif. Performance harus diukur sebagai power cost juga.

## 2. Metrics

Ukur:

```text
CPU average/peak
RSS memory
wakeups/minute
sysfs reads/minute
netlink events/minute
hardware writes/minute
log bytes/minute
startup latency
recovery latency
```

## 3. Scheduler budget

Current bounds:

```text
MIN_INTERVAL = 2s
MAX_INTERVAL = 90s
```

Unplugged heartbeat dapat lebih panjang. Angka harus divalidasi pada device nyata.

## 4. Event storm

```text
100 uevent
 → debounce/coalesce
 → one fresh snapshot
 → one decision
 → zero/one required mutation
```

Write count tidak boleh mengikuti event count.

## 5. Sysfs reads

Kelompokkan read yang dibutuhkan untuk satu snapshot. Hindari membuka/membaca node yang sama berkali-kali dalam satu evaluation jika tidak diperlukan.

Cache boleh digunakan untuk non-safety data, tetapi safety evidence harus memenuhi freshness requirement.

## 6. Logging

Normal polling tidak perlu log per cycle. Gunakan:

```text
state transition logs
operation start/end
error transition
rate-limited repeated error
```

## 7. Memory/queues

IPC/event queues harus bounded. Long-run test harus memastikan tidak ada growth karena stale event, client disconnect, atau log buffering.

## 8. EMA

EMA hanya optimization. Tidak boleh menurunkan safety sampling sampai policy kehilangan required evidence.

## 9. Measurement methodology

Bandingkan:

```text
idle + netlink healthy
idle + netlink unavailable
charging normal
limit reached
unplugged
error storm
suspend/resume
```

Catat baseline sebelum optimisasi dan after.

## 10. Regression gate

Threshold sebaiknya berbasis device class, bukan angka universal yang belum diukur. Significant regression pada wakeups/CPU/write frequency harus memblok release atau mendapat explicit justification.

## 11. Testing

```text
[ ] 24h synthetic runtime
[ ] event storm
[ ] netlink reconnect storm
[ ] repeated verification failure
[ ] IPC client flood
[ ] unplugged idle
[ ] suspend/resume
[ ] memory stability
```

## 12. Acceptance criteria

1. Idle overhead terukur.
2. Event storm tidak menghasilkan write storm.
3. Queue bounded.
4. Memory stabil pada long run.
5. Scheduler optimization tidak mengubah policy correctness.
6. Performance regression terdeteksi sebelum release.
