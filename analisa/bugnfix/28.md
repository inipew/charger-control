# 28 — Release Engineering

## 1. Tujuan

Release harus membuktikan bukan hanya bahwa binary compile, tetapi bahwa artifact, lifecycle, compatibility, security, recovery, dan safety invariants telah diverifikasi.

## 2. Pipeline

```text
fmt
 → clippy
 → unit
 → integration
 → property/fuzz
 → fault injection
 → security checks
 → cross-target build
 → artifact inspection
 → device matrix
 → release candidate
 → publish
```

## 3. Artifact identity

Setiap artifact harus memiliki:

```text
version
git commit SHA
target triple
Rust/toolchain identity
build profile
schema/profile versions
checksum
```

Binary production harus dapat dipetakan kembali ke source.

## 4. Reproducibility

Pin toolchain/dependencies bila memungkinkan. Jika build reproducibility sempurna tidak mungkin karena Android environment, simpan metadata yang menjelaskan perbedaan.

## 5. Release gates

Stop-ship jika:

```text
shutdown unsafe
direct hardware write exists
IPC privileged mutation unauthenticated
config silently falls back
ownership recovery nondeterministic
partial write unhandled
Fault can enable unsafe normal charging
runtime panic path exists
compatibility evidence missing
```

## 6. Upgrade

Safe upgrade:

```text
validate new artifact
 → ensure compatibility
 → request graceful old shutdown
 → finalize/recover ownership
 → install/start new binary
 → startup recovery
 → fresh snapshot
 → reconcile + verify
 → mark upgrade successful
```

## 7. Crash during upgrade

If new daemon crashes:

```text
journal remains
 → next startup recovery
```

Rollback tidak boleh menghapus journal atau config sebelum compatibility/migration selesai.

## 8. Schema migration

Config/profile/ownership schema migration harus:

```text
read old
 → validate
 → transform
 → validate new
 → atomic commit
```

Jika migration gagal, original state tetap tersedia.

## 9. Release notes

Wajib menyatakan:

```text
supported devices/profiles
new/changed control semantics
config migration
known limitations
Android lifecycle requirements
rollback instructions
```

## 10. Device validation

Release candidate harus diuji pada representative matrix:

```text
boot
reboot
plug/unplug
limit
thermal
fault
suspend/resume
external writer
crash
upgrade/rollback
```

## 11. Acceptance criteria

1. Artifact traceable.
2. Critical gates automated.
3. Upgrade/rollback crash-safe.
4. Schema migration tested.
5. Compatibility claims evidence-backed.
6. Known limitations documented.
7. Release cannot bypass safety gates.
