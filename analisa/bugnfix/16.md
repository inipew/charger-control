# 16 — Multi-Actor & Ownership Arbitration

## Aktor
Charging state dapat dipengaruhi oleh Android framework, vendor HAL/daemon, thermal service, kernel charger driver, user/CLI, Magisk module lain, dan ChargerControl.

## Invariant
- **I-ACTOR-001**: ChargerControl tidak boleh mengasumsikan dirinya satu-satunya writer.
- **I-ACTOR-002**: ownership adalah lease/kontrak operasional, bukan hak permanen atas sysfs.
- **I-ACTOR-003**: external mutation harus dapat dideteksi.
- **I-ACTOR-004**: daemon tidak boleh masuk write-fight loop tanpa bounded retry/backoff.

## Arbitration policy
Saat enabled:
- daemon memiliki ownership logical terhadap capability yang didukung;
- external mutation yang mengembalikan state berbeda direkonsiliasi sesuai policy;
- repeated interference meningkatkan failure/backoff;
- bila safety tidak dapat dijamin, fail-safe dan release ownership.

Saat disabled/unmanaged:
- daemon tidak menulis control node;
- daemon hanya boleh observe jika diperlukan untuk status.

## Jangan lawan thermal safety kernel
Jika kernel/vendor memiliki thermal protection yang lebih tinggi prioritasnya, ChargerControl tidak boleh menganggap write-nya dapat override safety layer tersebut. Policy user-level harus selalu subordinate terhadap hardware/kernel safety.

## Acceptance criteria
1. External write dapat disimulasikan dan dideteksi.
2. Ada batas jumlah retry dan backoff.
3. Unmanaged benar-benar tidak melakukan hardware mutation.
4. Log mencatat actor interference tanpa menyalahkan user secara ambigu.
5. Test memastikan tidak terjadi infinite write loop.
