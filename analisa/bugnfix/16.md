# 16 — Multi-Actor & Ownership Arbitration

## 1. Problem

Charging hardware dapat disentuh banyak actor. Daemon tidak boleh mengasumsikan bahwa setelah `set_charging()` berhasil, state akan tetap miliknya.

Potential writers:

```text
charger-control
Android framework
vendor HAL/daemon
thermal service
kernel driver
root CLI
other Magisk module
```

## 2. Ownership semantics

Ownership adalah **logical lease**:

```text
I am responsible for maintaining this intent
```

bukan:

```text
No other process can write sysfs
```

Sysfs write permission tidak menyediakan arbitration antar root actor.

## 3. Managed flow

```text
Desired
 ↓
apply
 ↓
verify
 ↓
monitor actual
 ↓
mismatch?
 ├─ no → steady state
 └─ yes → external modification/reconcile
```

## 4. External mutation classification

Mismatch dapat disebabkan:

```text
vendor policy
thermal protection
kernel transition
other root actor
stale read
node unavailable
```

Jangan langsung menyalahkan external actor tanpa evidence. Readback/provenance diperlukan.

## 5. Bounded reconciliation

```text
mismatch
 ↓
read fresh evidence
 ↓
reapply desired if safe
 ↓
verify
 ↓
repeat bounded times
 ↓
interference/degraded state
```

Tanpa bound, daemon dapat membuat write storm dan melawan vendor service.

## 6. Safety hierarchy

Kernel/hardware protection tetap authoritative. Jika kernel menolak write atau thermal subsystem memutus charging, userspace harus menerima outcome tersebut.

Tidak boleh ada retry agresif yang mencoba mengalahkan hardware safety.

## 7. Manual mode

Manual command harus memiliki explicit ownership/mode:

```text
Automatic
Manual
Unmanaged
```

Saat Manual aktif, automatic policy tidak boleh diam-diam menulis opposite target pada evaluation berikutnya.

Tetap gunakan controller/verification boundary.

## 8. Unmanaged

```text
Unmanaged
 → observe-only
 → no charging mutation
```

Status/diagnostics tetap boleh membaca hardware.

## 9. Arbitration state

Controller dapat menyimpan:

```text
owner
mode
intent_generation
last_verified_operation
interference_count
last_external_mismatch
next_reconcile
```

## 10. Race example

```text
T0 daemon desired OFF
T1 daemon writes OFF
T2 vendor writes ON
T3 daemon reads ON
T4 daemon writes OFF
T5 vendor writes ON
```

Setelah bounded retries, daemon harus masuk degraded/interference state, bukan loop selamanya.

## 11. Testing

Mock external actor:

```text
[ ] changes state after write
[ ] changes state after verify
[ ] changes one of multiple nodes
[ ] disappears/reappears
[ ] races manual command
[ ] repeated interference
```

## 12. Acceptance criteria

1. Ownership didefinisikan sebagai logical responsibility.
2. External mismatch dapat diobservasi.
3. Reconciliation bounded.
4. Infinite write fight impossible.
5. Kernel/vendor safety tidak dioverride.
6. Manual mode tidak dilawan automatic policy.
7. Unmanaged selalu zero charging writes.
