# 08 — Configuration & CLI

## Config contract
Configuration harus melalui satu pipeline:
```text
read bytes → parse → schema/version → validate → normalize → runtime
```

Implement:
```rust
Config::validate()
Config::normalize()
```

CLI dan daemon harus memanggil logic yang sama.

## Error semantics
```text
missing file → create defaults (jika memang expected)
parse error → reject
I/O error → reject
validation error → reject
unknown schema → reject/migrate explicitly
```
Jangan `unwrap_or_default()` untuk menyamarkan error.

## Safety validation
Minimal:
```text
resume_limit < charge_limit
charge_limit dalam range aman
thermal hysteresis > 0 dan bounded
max temperature reasonable
paths valid
intervals bounded
```

## Atomic write
```text
write temp
 → flush/fsync
 → rename
 → optional directory fsync
```
Preserve old config sampai new config committed.

## Reload
Config baru harus tervalidasi penuh sebelum mengganti config aktif. Jika gagal, runtime config lama tetap aktif. Perubahan policy-relevant harus memicu reconciliation; perubahan logging-only tidak perlu.

## CLI
CLI adalah client API, bukan second daemon core. Mutation dikirim via IPC/service layer yang sama. Exit code harus stabil dan didokumentasikan.

## Acceptance criteria
1. Corrupt TOML tidak ditimpa.
2. Direct file edit tetap tervalidasi.
3. Reload gagal atomic.
4. CLI tidak direct-write hardware.
5. Error dapat dibedakan parse/I/O/validation.
