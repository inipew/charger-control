# 08 — CONFIGURATION, VALIDATION & CLI CONTRACT

## Tujuan

Configuration harus predictable, atomic, versioned, dan konsisten antara CLI dan daemon.

## Single validation authority

```rust
impl Config {
    fn validate(&self) -> Result<(), ConfigError>;
    fn normalize(&mut self);
}
```

CLI dan daemon wajib menggunakan validator yang sama.

## Validation minimum

```text
50 <= charge_limit <= 100
0 < resume_limit < charge_limit
thermal hysteresis > 0
thermal resume < thermal cutoff
scheduler min <= scheduler max
retry/backoff valid
paths valid
```

Nilai batas exact harus memiliki tests.

## Load semantics

```text
file missing  → defaults/create
file valid    → use
parse invalid → reject/preserve
I/O failure   → reject
```

Tidak boleh silent fallback dari corrupt file ke default.

## Atomic write

```text
serialize
→ temporary file
→ flush
→ fsync
→ atomic rename
```

Backup/recovery strategy dapat ditambahkan jika diperlukan.

## Config versioning

Gunakan schema version:

```toml
version = 1
```

Perubahan schema berikutnya menggunakan migration terarah, bukan implicit defaulting.

## Runtime reload

```text
CLI change
→ validate
→ atomic persist
→ send ConfigReload
→ daemon reload
→ validate again
→ ConfigChanged
→ immediate reconciliation
```

CLI tidak boleh mengklaim daemon sudah reload jika acknowledgement belum diterima.

## Config change effects

Policy-affecting changes wajib menginvalidasi state yang tidak lagi relevan:

```text
charge_limit
resume_limit
thermal_cutoff
thermal hysteresis
enabled/disabled
profile
```

Prediction/EMA dapat di-reset jika parameter membuat historical estimate tidak valid.

## CLI contract

CLI harus membedakan:

```text
persisted
sent
acknowledged
applied
```

Keempat status bukan sinonim.

## Error handling

Jangan:

```rust
unwrap_or_default()
```

pada config read/parse yang safety-critical.

Gunakan semantic errors:

```text
ConfigNotFound
ConfigRead
ConfigParse
ConfigInvalid
ConfigWrite
ConfigMigration
DaemonUnavailable
ReloadRejected
```

## Acceptance

- satu validator;
- atomic persistence;
- schema version;
- corrupt config preserved;
- reload event-driven;
- immediate reconciliation;
- CLI acknowledgement truthful.
