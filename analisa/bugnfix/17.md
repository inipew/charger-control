# 17 — Suspend, Resume & Doze

## 1. Problem

Android userspace dapat berhenti dijadwalkan ketika suspend/Doze. Karena itu daemon tidak boleh mengklaim timer userspace sebagai real-time safety mechanism.

## 2. Core invariant

```text
monotonic deadline
        ↓
suspend
        ↓
resume
        ↓
DO NOT replay missed work
        ↓
fresh snapshot + actual read
        ↓
reconcile once
```

## 3. Missed timers

Misalnya daemon memiliki 20 deadline selama suspend. Jangan menjalankan 20 evaluation setelah resume. State dunia sudah berubah; hanya current evidence yang relevan.

```text
20 expired timers
 → coalesce
 → one fresh evaluation
```

## 4. Resume sequence

```text
resume detected
 ↓
mark cached snapshot stale
 ↓
reset/adjust EMA if needed
 ↓
read fresh battery snapshot
 ↓
read actual hardware control state
 ↓
policy
 ↓
reconcile
 ↓
verify
 ↓
schedule next wake
```

## 5. Retry deadline

Jika retry deadline lewat saat suspend, jangan langsung replay seluruh retry history. Jalankan satu retry/reconciliation dengan current generation. Backoff counter tetap bounded.

## 6. Monotonic time

`Instant` dipakai untuk:

```text
retry_at
verification deadlines
debounce
snapshot age
scheduler deadlines
```

Wall clock hanya untuk human-readable logs/metadata.

## 7. Thermal limitation

Userspace thermal policy tidak real-time ketika process tidak dijadwalkan. Karena itu kernel/charger hardware thermal protection harus menjadi backstop.

Dokumentasi produk harus jujur: daemon userspace bukan pengganti kernel thermal safety.

## 8. Netlink after resume

Resume dapat menghasilkan burst uevent. Debounce/coalesce harus mencegah duplicate evaluation/write.

```text
resume evaluation
 + 10 netlink events
 → one additional coalesced evaluation only if state changed
```

## 9. EMA

Long suspend dapat membuat `dt` besar dan rate tidak representatif. Reset EMA/history jika melewati configured discontinuity threshold.

## 10. Testing

```text
[ ] short suspend
[ ] long suspend
[ ] timer expires during suspend
[ ] retry expires during suspend
[ ] capacity changes during sleep
[ ] temperature changes during sleep
[ ] charger unplugged during sleep
[ ] charger plugged during sleep
[ ] netlink burst after resume
[ ] wall-clock adjustment
```

## 11. Acceptance criteria

1. Missed timer tidak direplay sebagai backlog.
2. Resume selalu fresh-read.
3. Stale cache tidak menjadi safety proof.
4. Thermal limitation terdokumentasi.
5. Netlink burst dicoalesce.
6. Retry menggunakan monotonic deadline.
7. Resume tidak menghasilkan write storm.
