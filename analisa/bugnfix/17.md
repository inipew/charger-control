# 17 — Suspend, Resume & Doze

## Tujuan
Menjamin state tetap benar ketika Android melakukan suspend, resume, Doze, screen-off, atau membatasi scheduling.

## Invariant
- **I-SLEEP-001**: monotonic time digunakan untuk deadline/retry/age.
- **I-SLEEP-002**: setelah resume harus ada reconciliation.
- **I-SLEEP-003**: netlink adalah wakeup accelerator, bukan satu-satunya correctness mechanism.
- **I-SLEEP-004**: daemon tidak boleh mengklaim thermal protection absolut selama deep sleep jika tidak ada mekanisme kernel wakeup.

## Resume sequence
```text
resume detected
 -> invalidate stale timing assumptions
 -> read fresh snapshot
 -> reconcile hardware
 -> verify
 -> restore normal scheduler
```

Timer yang terlewat selama suspend jangan dieksekusi sebagai backlog satu per satu. Gunakan deadline terbaru dan satu reconciliation.

## Thermal caveat
Jika device tidur dan daemon userspace tidak dijadwalkan, cutoff userspace tidak real-time. Safety-critical thermal behavior harus tetap berasal dari kernel/charger hardware. Daemon hanya lapisan policy tambahan.

## Acceptance criteria
1. Test suspend-like time jump tidak menyebabkan burst writes.
2. Resume selalu menghasilkan fresh snapshot.
3. Retry deadline menggunakan monotonic clock.
4. Netlink event setelah resume tidak menyebabkan duplicate operations.
