# 17 — Suspend, Resume & Doze

## Masalah
Android dapat suspend, Doze, screen-off, atau menunda userspace. Timer yang terlewat tidak boleh dieksekusi sebagai backlog dan daemon tidak boleh mengklaim real-time safety selama tidak scheduled.

## Invariant
- deadline/age/retry memakai monotonic clock;
- resume memicu fresh reconciliation;
- netlink bukan satu-satunya correctness mechanism;
- kernel/hardware adalah lapisan safety saat userspace tidur.

## Resume
```text
resume
 → invalidate stale timing assumptions
 → fresh snapshot
 → actual hardware read
 → reconcile
 → verify
 → schedule next deadline
```

## Missed timers
Jangan replay 20 timer yang expired selama suspend. Lakukan satu reconciliation berdasarkan state terbaru.

## Thermal limitation
Jika daemon userspace tidak dijadwalkan selama deep sleep, cutoff userspace tidak real-time. Kernel/charger safety harus menjadi backstop. Dokumentasi harus menyatakan limitation ini dengan jelas.

## Netlink
Event yang muncul setelah resume boleh mempercepat reconciliation tetapi tidak boleh menyebabkan duplicate write setelah state sudah verified.

## Testing
Simulasikan:
```text
long sleep
clock jump
resume with changed capacity/temp
netlink burst after resume
retry deadline passed during sleep
```

## Acceptance criteria
1. Tidak ada burst write setelah suspend.
2. Resume selalu menggunakan snapshot fresh.
3. Thermal limitation documented.
4. Retry deadline tidak bergantung wall clock.
